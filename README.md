# 灵核公寓 · V0.7.0「活着的公寓」垂直切片

**这是一轮核心玩法重做，不是新增一批按钮。** 主页现在只呈现同一座公寓：核心炉产电、星光温室消耗电力生产食物，哨戒台用同一份电力抵御不断逼近的污染体。炉温过高、温室孢子、电网故障和最终围攻会迫使你调动灵核；每次换岗都改变其它房间的状态。

[在线试玩](https://kunlong-luo.github.io/monster-apartment/) · [旧版功能参考 /legacy](https://kunlong-luo.github.io/monster-apartment/legacy/)

## 开始玩：不用学几十个按钮

1. 点击「开始守护公寓」进入自然运行的夜晚（120 刻）。
2. 看电力、食物、核心与炉温四项直接反馈；观察公寓右侧出现并移动的敌人。
3. **点击下方的灵核，再点击想去的房间**；桌面也可以将卡片拖到房间。岗位交换会影响供电、食物产出或守卫能力。
4. 看炉温过载、温室孢子和电网故障如何连锁影响全楼。适时调换修缮、经营与守护灵核，而不是点多个独立操作页。
5. 核心坚持 120 刻就是胜利；失败后保留知识重新调度阵容。

### 目前的真实边界

这是验证核心循环的 **首个可玩版本**，不是完成度很高的模拟经营游戏。建筑和入侵者使用 Phaser 程序化场景，危机按确定时间触发；没有多个大型关卡、复杂动画或完整音效。需要实测策略是否多样、调岗是否有足够的机会成本。

**存档保护：** 新原型只写入 `monster-apartment:living:v1`，会读取此前已收集的灵核，但不覆盖旧版 `monster-apartment:save:v1`。以前的六房五夜/塔防代码暂放在 `/legacy` 用于回归与对照，不再是主页主玩法。

## 2. 安装与启动

```bash
node -v                 # 应为 v24.x
npm install -g pnpm@12.13.0
pnpm -v                 # 应为 12.13.0
pnpm install
pnpm dev                # http://127.0.0.1:3000/
```

生产构建：`pnpm build && pnpm start`（同样监听 127.0.0.1:3000）。

## 3. 提交前门禁

```bash
pnpm check:stable-deps  # 依赖必须为精确 semver
pnpm typecheck          # tsc --noEmit
pnpm lint               # ESLint flat config，0 warning
pnpm test:rules         # node --test，6 条
pnpm test               # Vitest 规则、战斗、存档与养成回归
pnpm build              # Next 16 Turbopack
pnpm e2e                # Playwright 浏览器交互与响应式验证（CI 使用系统 Chrome）
```

CI（`.github/workflows/quality.yml`）使用 `pnpm install --frozen-lockfile`，分 `checks` 与 `e2e` 两个 job。

## 5. 迁移变更（V0.1.2 → V0.2.0）

- Vite 8 SPA → Next.js 16 App Router；删除 `index.html`、`src/main.tsx`、`src/App.tsx`、`vite.config.ts`、`preview/`。
- 规则层 JS → TS 单文件，`public/playable.html` 保持冻结、不再共享规则实现。
- 全量组件化：UI primitive 与业务面板分层，业务组件不再直接写裸样式的 `<button>` / `<section>`。
- 清掉三个已无引用的遗留文件（`src/style.css`、`src/store/useGameStore.ts`、`src/game/ApartmentScene.ts`），避免同名 store / 场景双份实现。
- 端口 5173 → 3000；变量与 API 未变。

## 6. 已知限制

- TypeScript 固定 6.0.3：`typescript-eslint` 尚不支持 TypeScript 7 的编译器 API。
- Phaser 通过 `next/dynamic` 独立分包，进入画面时会短暂显示“正在加载公寓地图…”。
- 数值平衡：最优布局五天可达 232 金币 / 满意度 63（目标 135 / 55）；空置房会亏损。
- 已加入浏览器本地存档与英文界面；仍无音效、云端账号同步与 Electron 打包。

## V0.4.0 第二阶段：住户偏好与每日经营策略（PR #5）

- 六间房拥有**固定特质**：1/5 潮湿（适合史莱姆），2 向阳（火精灵），3/6 安静（幽灵），4 石墙（石像鬼）。相符每天 **+3 金币、+2 满意度**；不符每天 **-1 金币、-1 满意度**。移动和交换房间会改变下一晚结果。
- 每天可选择一次经营策略：**稳健（0/0）**、**办派对（-5 金币、+8 满意度）**、**省开支（+6 金币、-6 满意度）**。策略在夜间结算时生效，结算后回到稳健，事件仍依五天固定顺序发生。
- 经营面板新增偏好与策略收益；房间列表显示契合信息，公寓画面显示永久房间特征。支持完整中英文翻译及夜间日志明细。
- 继续沿用 `monster-apartment:save:v1` 存档键。旧版 V1 存档中没有策略字段的记录会自动补齐 `steady`，不会重置玩家进度。新存档对策略与记录字段进行严格校验。
- 目标仍为五天金币至少 135 和满意度至少 55；新增规则可能改变达成难度，正式发布前需由真人试玩并做数值平衡。
- **状态：** 第二阶段 PR #5 已合并至 main，保留桌面单屏与手机 Tab 布局。

## V0.4.0 第三阶段：五晚可选事件与结算反馈（直接提交 main）

- 在“经营”面板中，**每晚出现不同主题的事件抉择**：第 1 夜巡逻、第 2 夜水管、第 3 夜访客、第 4 夜供暖、第 5 夜评选。
- 三个选项：**顺其自然**（不改变旧版结果）、**主动照顾**（用金币换满意度，若对应怪物在场可获得返还）、**追求利润**（增加金币，牺牲满意度）。点击可重新选择，结束当晚后自动复位。
- 每晚投入方案因剧情不同：巡逻 -3 金币/+5 满意度（有石像鬼返还 3）、修管 -5/+7（有史莱姆返还 5）、招待访客 -4/+6（有幽灵返还 4）、供暖升级 -5/+8（有火精灵返还 4）、年度布置 -8/+10（有石像鬼返还 4）。
- 利润方案分别为 +5/-4、+6/-6、+7/-6、+6/-5、+9/-8（金钱/满意度）。
- 事件应对独立于原有每日经营策略和原本五个固定夜间事件；经营面板新增选择收益预览，结算时计入金币、满意度与中英文日志。
- 每次结算状态提示有轻微动画，系统开启“减少动态效果”时禁用；不增加额外滚动区域。
- 继续沿用旧 localStorage V1 存档键，没有新选择字段的旧存档自动按“顺其自然”恢复。新增 Vitest 与 Playwright 检查事件差异、存档、手机操作和减少动画设置。
- 开发直接向 `main` 提交；自动化检查通过并由 GitHub Pages 显示发布成功后，才视为线上验证通过。

## V0.4.0 第四阶段：动态与数值回归（2026-10-22）

- 四种怪物增加不同幅度/频率的程序化待机动作；只动角色，不动墙壁家具和阴影。
- 招募、搬家和房间交换会在变化房间显示短暂反馈；首屏初次载入、本地存档恢复、普通选房不会无意义地重放特效。
- 玩家启用 `prefers-reduced-motion` 后，上述动态图像及状态栏微动画全部禁用。
- 自动验证三条五天经营路径：只追求金币的错误布局会输、同样布局通过每日关怀可以获胜、一直逐利虽然金币更多但满意度更差；契合租客的基础布局依然能赢。
- 保留六房与五晚现有规则、金币/满意度目标、V1 存档、双语、桌面单屏和手机四标签，不增新依赖。
