# 《灵核公寓》V0.9.8 · 月光街的住户委托和街区口碑

这是**模拟经营 / 建造 / 住户生活**小游戏，而不是塔防或资源危机游戏。

[**进入游戏**](https://kunlong-luo.github.io/monster-apartment/) · [前代生存原型 /survival](https://kunlong-luo.github.io/monster-apartment/survival/) · [最早六房经营版 /legacy](https://kunlong-luo.github.io/monster-apartment/legacy/)

## 玩家在这里做什么

你拥有一座三层六格的破旧小公寓和 105 星币。第一位住户「芽核」已经搬入。其他灵核在门外等待，你需要亲手建新房、让他们入住，并摆放住户喜欢的家具。

- **点空房**：选择卧室、浴室、工坊或花房；房型花费 30–38 星币。
- **点建好的空房**：选择门口正在等候的灵核入住。
- **点有人住的房间**：布置盆栽、萤灯或故事书；家具会实际改变住户幸福度。
- **观察一天**：人物按照时间睡觉、做事、散步、串门；清晨自动收房租，租金由实际幸福度决定。
- **把朋友安排在相邻房间**：邻居产生羁绊，两天后会解锁发生在这座楼里的小故事。
- **迎接新客**：蕨尾兔和月影雀在不同天数到访；用收入扩建，争取最初八天结束时有至少 3 位住户且平均幸福度达到 70；之后公寓不会强制结束。

每个八天经营周期结束都会按当时的入住与幸福度发放里程碑奖励，之后继续游戏；随时可重新开一栋楼。没有需要反复点的「结束一天」，也没有强制抽卡或独立战斗页。

## V0.9.8：长期生活有了值得布局的章节任务

第九天开始，每个八天章节都会出现**一份由具体住户发起的委托**，而不再只让所有人机械地重复收租。委托直接使用房间、装修、现实中的串门和羁绊，不要求玩家点击新的任务按钮。

- **露珠灵的睡前读书会**：住在浴室、摆上故事书，并和芽核成为有串门羁绊的邻居。
- **灯甲虫的夜光修理铺**：住进工坊、点亮萤灯，与露珠灵建立邻居关系。
- **蕨尾兔的窗边种子会**：住进花房、布置盆栽，和芽核成为真正的朋友。
- **月影雀的月下故事集**：住进工坊、摆上故事书，与灯甲虫建立羁绊。

每份委托明确标出 3 项条件和实时进度，出现在原有月光街手记上；手机保留精简展示，不增加独立任务页。只要在八天章节结束时全部满足，即额外获得首次 24 星币，重复完成获得 10 星币；首次成功还会**永久解锁 +1 星币/天街区口碑赞助**。四份委托至多可积累 +4 星币/天，完成过的成就可永久保留，构成长期成长。未完成不会罚款，下一个章节继续轮换目标。

核心逻辑由旧 V1 存档中已有的 `rooms`、`bonds`、`seen` 派生，不新增必须存在的存档字段。委托的首次完成记录存进原有去重记录，并在长时间运行时优先保留，避免已解锁的赞助消失。日常进账显示房租、制作、赠礼和口碑；搬家收益预览同步使用完整日进账，保持账目一致。

**未完成部分**：这版让既有六房五人有了实际持续经营的方向，但未扩充第七间房或正式角色资产；后续需要独立设计可扩建的街区与不牺牲手机单屏的建筑布局。

## V0.9.7：长期经营与阶段性心愿

- **第八天不再强制结束**：原先 `tick = 96` 的终局改为首个八天阶段的结算点。每完成八天，系统根据当前入住和幸福度结算纪念星币（达标 +18，否则 +6），并通过生活手记叙述，而不是用“游戏结束”阻断建造。
- **住户有变化的长期心愿**：第九天起，五个住户会错开节奏，每三天轮换想休息、找灵感和见好朋友。卧室/浴室或故事书满足休息；工坊/花房或萤灯满足灵感；与**真实串门建立过羁绊**的好友住得相邻时满足陪伴。满足 +12 幸福度，未满足 -4，影响每日租金。
- **从房间直接观察**：住户名字牌上增加极简满足状态标记，选中住户所在房间会看到当前心愿和幸福度增减，无额外操作按钮。玩家仍只通过建房、入住、家具和搬迁来解决问题。
- **旧存档继续游玩**：读取旧版 `phase: complete` 的 V1 通关存档时自动恢复经营，**保留币、住户、房型、家具、邻居羁绊与日志**；存档键仍为 `monster-apartment:cozy:v1`，没有新增必须存在的字段。
- **长期安全**：每日出租、访客行为和里程碑照常结算；滚动日志与事件去重集合有上限，羁绊等级限制在有效上限。补充百日模拟与真实浏览器的旧档恢复、心愿装修、里程碑、手机单屏回归。

当前可持续运营，但仍是六房五位住户的轻量沙盒；正式角色美术与更多可扩建街区尚未完成。

## V0.9.6：住户开始经营自己的生活

本阶段把此前仅供观看的房间和串门行为，连接到明确可预测的经营回报。玩家依然只需要**建造、入住、装修、搬迁**，没有增加一排空洞的功能按钮。

- **房型用途**：有住户的工坊每天制作 +3 星币，搭配萤灯则 +5；有住户的花房每天收获 +1，搭配盆栽则 +3。空房不生产。产出直接和房租一起在清晨结算。
- **邻里照料**：住户邻近花房或浴室时获得舒适度 +1；花房配盆栽、浴室配故事书时，邻居享受 +4。改善住户幸福度会影响实际房租，形成建造与布局策略。
- **真正的羁绊**：只有相邻、彼此喜欢且在当天确实能串门的住户才逐日积累羁绊。每等级为对应邻居带来 +2 幸福度（最多 +6）；羁绊达到两天，双方每天合计带来 +2 星币邻里赠礼。搬远后这些近邻收益暂停；重新成为邻居又会恢复。
- **收入可解释**：公寓界面的“每日进账”是房租、制作与邻里赠礼的总和；场景手记注明分项；选中住户所在房间可看到邻里照料与真实羁绊增加的幸福度。搬迁收益预览也计入真实日进账变动。
- **存档兼容**：只使用原本的 `rooms`、`bonds`、`tick` 等 V1 字段，不引入新的付费货币或额外存档字段。原有已形成的羁绊会立即获得新的经营效果。新增 Vitest 和 Playwright 回归验证收租、搬迁、布局与旧存档。
- V0.9.6 当时仍是 8 天的短循环；V0.9.7 已将其延伸为可持续经营，并新增阶段性住户心愿。

## V0.9.5：住户行为从图标摇晃改为场景导演

- 新增纯函数 `cozy-resident-performance.ts`，根据已保存的游戏时间、住户身份和房间类型，决定四帧姿态、面向方向、房间内站位。工作回到工作台，睡觉回到床边，闲逛会经过不同位置；不另存数据、不增加经济状态。
- 原创 SVG 角色拆成四帧变体：迈步时的双脚和手臂、工作表情、不同房型工具（植物水壶、浴巾、工坊手槌、羽毛刷），来访带小杯点心。不再只靠统一的 CSS 左右摇摆。
- 房间人物坐标随模拟时刻更新，使用有限位移动画平滑走到下一地点。实际触发串门时，访问者出现在邻居房中，与已有楼梯线路同步；不是凭空出现新的按钮。
- 新增纯逻辑测试和 Playwright 真机浏览器回归，覆盖驻点、行走、转身、工具、串门、暂停和减少动画偏好；手机端与 V1 存档保持兼容。
- **仍不等于完成正式美术制作**：这次是程序化 SVG 角色的行为帧和场景调度升级，不冒充经过专业逐帧绘制的动画资产集。

## V0.9.4：旧屋修缮与住户美术可读性

重点从 HUD 特效转向**场景内容和材质本身**：

- 所有待建造房间改为原创矢量旧屋场景：透视墙体、木地板、旧窗、破旧木板、积灰与六种随机性为零的遗留物件变体。移除了原先五间重复的空框和中央大“＋”。
- 建造仍由点击房间选择房型；建造成功后旧屋 SVG 被所选房型的室内空间取代，沿用 V0.9.2 的建造揭幕演出。
- 四种房型增加一组新的手工细节：卧室布料褶皱、浴室湿润瓷砖与管件、工坊木纹与工具、花房叶片与吊篮。材质和家具使用同一 SVG 投影坐标系，能由游戏状态实时切换。
- 提高住户在桌面和手机画面中的视觉体量，并保留已有家具遮挡、睡眠和工作动作；缩小旧屋操作提示，使房间本身可看清。
- 增加 Playwright 回归，验证每个待建造房间的不同旧屋结构、旧屋→房型的真实变化、重新载入存档后保持建筑类型，以及手机无遮挡/无滚动。

**未改变**：建筑数量、房型价格、租金、幸福度、邻居行为、存档格式、键盘交互、技术栈和已有的纯 Phaser 光效层。当前仍是 SVG 场景 + Phaser 光影的混合渲染，并非正式手绘资产集。

## V0.9.3：公寓的公共空间与住户通路

这一阶段修复此前最突兀的空间问题：六个独立房间不再像拼贴画，而是通过贯穿三层的楼梯井、公共窗户和每户房门连接成一栋建筑。

- 新增 `CozyStairwell`：三层共享楼梯、扶手、楼层平台和中庭窗户；横跨整个建筑高度，房间不再直接拼接。
- 新建房间立刻拥有通向楼梯的实体门；仍是原有房间按钮，操作方式和键盘无障碍支持均不变。
- 当新住户入住某层时，对应楼梯间窗光会点亮；当真正触发 `cozyVisits` 邻居串门时，楼梯中显示访客路径和动态光迹，路径由游戏状态驱动。
- Phaser 氛围层对楼梯井重新对齐，并绘制基于真实访问状态的路径光点；不是纯随机装饰。
- 更新桌面/手机 E2E：验证楼梯覆盖三层、居民入住后对应楼层点灯、串门路线、无页面滚动与可点击房间。
- 所有金币、幸福度、租金、拜访判定以及 V1 存档都保持兼容，且没有增加新的操作按钮。

**范围限制**：这是建筑空间与动态演出的实质性升级，场景依然是 React SVG + Phaser 光效的混合结构；并未实现高成本手绘贴图或者全部角色帧动画替换。

## V0.9.2：房间行为演出与昼夜气象

- 建造、入住、摆放家具均由真实经营操作驱动；仅在成功变更房间状态后才出现对应的建筑揭幕、迎新光环、布置光点，不额外增加 UI 操作。
- 游戏时钟被映射为黎明、白天、黄昏、夜晚四个场景光照阶段；第 3、6 天出现非玩法性的细雨。美术天气固定且可复现，不消耗资源，也不改变经营结算。
- 暂停后世界环境动效停止，玩家依然可以观察和调整房间，操作演出不会被暂停状态冻结；系统减少动态效果时新增动画关闭。
- 新增纯函数测试和真实浏览器验证，覆盖建造→入住→装修的演出、重开不残留演出、已有存档驱动的天气与移动端无额外按钮。
- 仍使用 `monster-apartment:cozy:v1` 保存全部经营数据，不增加美术字段，不涉及模拟数值调整。

**仍需升级**：场景继续使用原创 SVG 家具与角色 + Phaser 氛围层。下一步应引入风格一致的正式贴图/帧动画素材，并进一步整合到 Phaser 的深度排序与相机体系。不能将当前的程序化演出误认为高规格绘制资产已经完成。

## V0.9.1：角色与室内空间融合（第二阶段）

本阶段不是简单多加几段 CSS 装饰，而是让角色跟房间空间、模拟时间共享表现：

- 原创灵核 SVG puppet 增加独立的四肢、眼睛和触须状态；睡觉闭眼、日常眨眼、做事摆手、走动迈步，房间里移除悬浮的状态表情图标。
- 新增 `cozy-room-foreground.tsx`：床沿被褥、浴缸前壁、工作台、花坛在**角色之后**绘制，实现真实前后遮挡；睡梦、泡泡、火花和花粉与房型及当前活动对应。
- 新增首页 `CozyAtmosphereScene` 和 `CozyWorldEffects`，通过单一透明 Phaser Canvas 对真实建造、住户、房型和时间进行局部照明、微粒与灯光渲染，原来房间点击目标保持为可访问的 DOM 按钮。
- 渲染基于 `Phaser.Scale.RESIZE` 响应桌面及手机，且不依赖远程字体/贴图；暂停和系统减少动画配置限制背景动效。
- E2E 新增 Phaser Canvas 存在与穿透点击、居民与家具前景叠层、移动端减少动画等检查。

**当前边界**：Phaser 现已进入首页视觉渲染流程，但房间几何、家具与角色 SVG 仍由 React 绘制。尚未完成将全套场景/贴图/角色动画迁移进 Phaser 的工程，不能当作商业级美术资产已交付。现有经营规则及 `monster-apartment:cozy:v1` 存档格式均未改变。

## V0.9.0：从平面插画到连续游戏场景（第一阶段）

这轮改动不增加操作按钮，不修改经营数值、存档版本或建造规则，集中处理影响游戏质感的场景问题：

- **环境层次**：新增 `cozy-street-backdrop.tsx` 的连续 SVG 街区；远处天际线、屋顶、月光、路灯、前景街道和植物共同形成纵深，而不是空渐变背景。
- **建筑材质**：加深立柱与楼板投影、修正外框与地面的分层，强化三层剖面建筑的厚度。
- **房间空间**：四类房型增加石膏纹理、天花与边墙透视、窗户投光、墙灯和地面阴影；灯光与家具处于同一空间。
- **生活演出**：浴室蒸汽、工坊火光、花房微光和角色的工作／散步／睡眠动作具备不同节奏；尊重系统的“减少动态效果”偏好。
- **验证**：为连续街景和减少动态效果添加 Playwright 回归断言，既有建造、入住、迁居、装修、移动端无滚动测试继续沿用。

**仍未完成的部分**：这还是 React DOM + SVG 的游戏舞台，并非完整的 Phaser 首页场景，也不具备手绘高规格贴图、完整角色骨骼动画或音效。V0.9.0 当前属于可逐步验收的场景升级，不能将 CSS/SVG 动效等同于完整商业游戏美术资产。CI 通过和浏览器截图复核后才视为可发布版本。

## V0.8.2：视觉改造

这版重点修正上一轮“网页玩具感”：公寓绘制为一栋连续的楼，而不是六个色块；四类房间都有独立 SVG 室内布景与家具（床、浴缸、工具台、温室花架），窗外有月光城市、窗框和墙板。家具与角色在同一张房间画面中分前后景摆放，角色使用无卡片底框的原创剪影。建筑和场景在白天与夜晚有不同色温。建造、入住、装修和邻居串门的真实规则均保留。

原型依然缺少完整逐帧角色动画、音效、更多家具与自由建墙；当前视觉是统一的原创矢量插画方向，尚不是一套高规格手绘或像素美术资产。桌面和手机的真实浏览器截图已经纳入 CI 视觉审查附件。

## 当前真实边界

**V0.8 是第一条可玩闭环，不是完成的商业游戏。** 这是 DOM + 原创灵核 SVG 组合的切面公寓，住户活动暂以房间内的动态表现体现，尚没有完整家具编辑器、自由建墙或复杂 AI 寻路。故事基于居住条件与邻居关系触发，并非固定剧情按钮。

### 存档保护

新首页写入独立键 \`monster-apartment:cozy:v1\`；V0.7 的 \`monster-apartment:living:v1\` 和更早的 \`monster-apartment:save:v1\` 保留不动，分别可在 \`/survival/\` 和 \`/legacy/\` 打开。新玩法的候选住户使用已有原创角色，不需要从旧游戏的抽卡库付费解锁。

## 2. 安装与启动

```bash
node -v                 # 应为 v24.x
npm install -g pnpm@12.13.0
pnpm -v                 # 应为 12.13.0
pnpm install
pnpm dev                # http://127.0.0.1:3000/
```

生产构建：`pnpm build && pnpm start`（同样监听 127.0.0.1:3000）。

```bash
pnpm check:stable-deps  # 依赖必须为精确 semver
pnpm typecheck          # tsc --noEmit
pnpm lint               # ESLint flat config，0 warning
pnpm test:rules         # node --test，6 条
pnpm test               # Vitest 规则、战斗、存档与养成回归
pnpm build              # Next 16 Turbopack
```

## V0.4.0 第二阶段：住户偏好与每日经营策略（PR #5）

- 六间房拥有**固定特质**：1/5 潮湿（适合史莱姆），2 向阳（火精灵），3/6 安静（幽灵），4 石墙（石像鬼）。相符每天 **+3 金币、+2 满意度**；不符每天 **-1 金币、-1 满意度**。移动和交换房间会改变下一晚结果。
