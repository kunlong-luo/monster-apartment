## 0. 产品北极星、入口与角色规则

用户从独立的全屏“欢迎页”看到统一封面；点击唯一主 CTA“开始游戏/继续游戏”进入大厅；由剧情引导进入真正的召唤场景，抽得不同的**成年、性感、有辨识度的人形女角色**；解锁角色卡、独立房间、交谈、动态演出与派工，并可选择查看与她契约相连的**独特野兽伙伴**。野兽是有力量感的异兽/守护者，不是可爱宠物、也不挤占主要女性角色的卡面视觉中心。

主要路径（不新增混乱的世界级菜单）：欢迎页（独立 UI 状态） → 大厅（现有 /） → /characters/#summon-screen（单抽/十连） → 卡牌揭晓 → 人物收藏 → 人物房间/工坊。是否初始展示欢迎页由本地已进入标志控制；已有玩家的存档不能因更新清空。剧情人物仍可通过主线认识；“拥有可派工/收藏的契约形态”由卡池决定，避免抽不到关键人物导致剧情断档。

首批玩家视角的人物：月纱（红月契约）、泉泡（皎月狼契约）、青枝（荆棘花契约）、炽角（熔炉铠兽契约）。沿用已有的 yuesha/brook/fern/cinder 与 brook-tide/fern-spring/cinder-ember/yuesha-vow/yuesha-eclipse **内部 ID，不迁移或重置玩家存档**。二张月纱卡为同一人物的不同品阶/契约，不伪装成不同长相的两个人。

**不做：**用一张已含“开始游戏”“单抽”“概率”等文字的海报覆盖整页、在透明层上堆不可见假按钮；用换发色的一张脸复制全部人物；拿背景场景替代头像；让异兽变成再次抽取的宠物球；虚构限时活动、充值、VIP、未实现的剧情或未实际发生的抽卡结果。当前真实概率仍以程序内 46/31/17/5/1 和实际保底为准；参考图中的 3% SSR、72/90、倒计时和货币数值均不代表游戏存档真值。

## 3. “不能同脸建模”强制检查

- **先锁骨相，再定发型与衣服。** 至少对比脸型宽窄、下颌角、颧骨高度、眼睛形状与眼距、鼻梁与鼻尖、唇厚、眉弓、年龄成熟度、面部表情六类要素；不得只换发色、服装与美颜滤镜。
- 单独生成四张相同角度、相同光照的无装饰脸部中性肖像排成 contact sheet；抽掉头发颜色和衣服仍至少能通过骨相认出四个不同的人。
- 固定“角色锁脸参考”后，所有服装/剧情变体须参照同一人的脸；保留角色表情变化，不要每次重新随机长相。
- 发放必须是明确成年的角色；性感靠服装剪裁、姿态、材质、目光、构图表现，保留职业辨识和叙事合理性，不制造露骨内容。
- 如果有两张图像面部几乎相同、左右手出错、兽体结构不合理或视觉过度磨皮，该批次退回重做；**不能靠调色/硬拉伸蒙混过关**。

## 4. 四位美女与四兽唯一搭配

具体身份、面部特征、装备配色、独立异兽形体见相邻的《CHARACTER_AND_BEAST_BIBLE.md》。**野兽不是人形女性的替身。**剧情里野兽可以守护、试炼、对立或结契，而不是全都变成肩上萌宠。女性角色仍是 UI 中获得、成长、对话的中心。

## 5. 技术接入、CI 和可玩性验收

- 现有栈为 Next.js / TypeScript / Tailwind CSS / Motion / PixiJS；继续在主分支提交，保持七个现有世界级页面与一套导航目的地。
- 欢迎页要独立 UI 状态与延迟背景加载；正式游戏按钮与 logo、图片**分层**，点击盒、键盘焦点和触控区域不依赖图上的像素。
- 资源通过角色 ID → manifest → 动态加载，失效时回退旧的真实高质量素材，而不是一张多人海报裁出四个一样的脸；小头像与全身 CG 分别设计 sizes 与裁切。
- 事件逻辑、抽卡公示概率、软硬保底、跨标签存档与损坏存档保护保持原义。视觉图的虚构 72/90 和 3% 不可直接复制为程序事实。
- 至少有以下 Playwright 断言：欢迎按钮进入大厅；刷新/再次进入不会重置资源；召唤后实际收藏更新；四人头像不相同；四兽资产路径不同；移动端无覆盖/无水平滚动；可减少动画；失效资源可用。
- 每阶段同时存一张桌面、一张手机“实际运行截图”到评审报告；不把概念海报截图当作真实运行截图。
- 性能目标（待实际测量后冻结）：首页关键场景图优先 WebP/AVIF、有响应式 srcset；首屏避免同时加载全部四个 1536px 人物与全部兽图；减少动画模式关闭持续粒子；不在切换场景时重复解码同一大图。
