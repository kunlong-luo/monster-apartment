# R12.1 · 首页导航重制规格：电影式画面 + 轻量世界入口

> 状态：**设计决策草案 / 待实施与截图验收**，不是已经合并的前端改版。反馈源：用户明确指出首页七按钮菜单栏“不好看”。不能仅改配色、圆角、边框厚度来宣称已解决。

## 1. 当前实现与需要保留的约束

- `src/components/game/gothic-lobby.tsx` 首页通过 `GothicDock` 同时显示七个 `WORLD_NAV` 目的地，`src/components/game/gothic-hud.tsx` 渲染语义导航。当前 7 项直接平铺，视觉上更像网页功能栏，而不是绘景中的有层次游戏入口。
- 底栏样式来自 `gothic-hud.tsx`、`gothic-lobby.css` 和 `gothic-reference-layout.css`；需要精确合并同一组件的样式来源。**不要**在末尾继续追加 `!important` 覆盖。
- 保留 `CANONICAL_GAME_NAV` 的七个真实目的地、顺序与既有路由：大厅、公寓、工坊、角色、委托、探索、仓库。不能擅自改路由、菜单文案、召唤/订单入口、存档或实际业务动作。
- 保留用户已认可的桌面四区绘景骨架：左侧四人肖像、中间主女主和对话留白、右侧月蚀活动与三张真实海报、底部导航。**重制的是入口的视觉与交互层级，而不是恢复为左右大块 KPI 看板**。
- 其他六个场景继续沿用唯一 `GameSceneNavigation`（大厅/地点、Esc 关闭）；R12 不能重新把底部七条菜单复制到每个页面。

## 2. 推荐方案：主入口 + 收起的世界地图

**大原则**：一屏只存在一个清晰的主互动呼唤，场景人物占画面主导，导航退到边缘；完整地点始终可两步内到达。

### PC ≥1100px（1440×900 / 1648×928）

- 保留中央画作、左肖像、右海报及原剧情热点区域。
- 底部由「七个平铺的大按钮」改成**低高度、半透明深色金属纹理的游戏导航装饰带**，默认显示四个常用世界入口：**公寓 / 工坊 / 角色 / 月光街**；右端一个「全部地点」折叠入口。大厅是当前位置，不应重复占用一项大按钮。
- 「全部地点」展开使用从同一 `WORLD_NAV` 注册表生成的七项地点清单，包含**委托、仓库和大厅**；不是增加第八条游戏路由，已有深链可直接前往，保证不需要隐藏的第四步。委托、仓库也保留其现有场景内入口。
- 「继续经营」如需强调，只能复用已存在的可行路线/当前主线行为，不能新增虚构的结算操作。主舞台焦点仍是人物与互动话语泡，而不是弹出一整列 CTA。
- 默认带宽建议 `≤800px`（依真实布局再确认）、底栏视觉高度 `≤64px`，不挡右侧海报、人物脚部与对话；展开面板需独立层级、适时避让左右叙事卡，并有清晰关闭按钮。
- 图标沿用 **Lucide** 的语义图标，描线 1.5–1.8px，禁止 Sparkles、重复彩色徽章及无意义发光；不把 emoji 用作导航主图标。

### Mobile ≤600px（390×844 / 390×550）

- 手机默认显示最多 **三条核心目的地 + 一个「全部地点」**，或在窄屏仅保留「全部地点」和当前目标入口（依据截图确定）；不硬塞桌面的五个按钮，最小可点击热区 **44×44 CSS px**。
- 文案至少清楚区分「工坊自动生产」「委托履约」两个真实系统的入口。完整地点以自适应上弹面板展开，滚动只发生在面板内，顶部资源栏仍可读，屏幕不出现横向滚动。
- 支持安全区 `env(safe-area-inset-bottom)`，低高屏 `390×550` 也不能遮住月纱对话/召唤主要按钮，阅读时导航不阻塞聚焦元素。
- 面板打开后：Tab 进入；Esc 关闭并将焦点还给触发按钮；点击外部关闭；打开其他游戏弹窗时按统一层级处理。减少动态效果时直接完成展示、不依赖位移动画才能操作。

### 视觉系统

- 基色仍引用 `gothic-premium-tokens.css`：`--craft-night`、`--craft-panel`、`--craft-wine`、`--craft-brass`、`--craft-champagne`、`--craft-ivory`，不得复制另一个全局「高级紫金」色板。
- 材质：低对比真暗铜、单道细金边、单层柔阴影，限制大面积黑色不透明挡画；选中地点用局部酒红/短发光，普通按钮不加大面积渐变。
- 字体层级：中文目的地可读优先于无意义英文眉题；标签不小于能在 390px 屏真实阅读的尺寸，利用 `text-wrap` 和 `aria-label`，不要靠 CSS 变形挤压。
- 动效：已有 Motion 用于入口展开/收起、短焦点反馈，最多局部 150–220ms；减少动效时直接显示。不引入自制动画引擎、无屏幕级多层蒙版。

## 3. 组件与 CSS 重构建议

1. 以 `CANONICAL_GAME_NAV` 作为唯一业务数据源。新组件可以在 `gothic-hud.tsx` 附近拆分出 `LobbyPrimaryNav` 与 `LobbyWorldMenu`，但不得硬编码第二套地点对象/URL。
2. 将 `gothic-lobby.css`（当前约 149–206 行）与 `gothic-reference-layout.css`（约 280–307 行）的 `gothic-dock--cinematic` 规则迁入**一处**有清晰桌面/手机断点的入口视觉文件；删除被替代的旧规则，避免叠加 `body` 权重与 `!important`。
3. `GameSceneNavigation` 只用于正式非大厅路由（当前已做），与首页主菜单共享图标/目的地语义，视觉可以轻量但不能出现相互矛盾的导航层级。
4. 首次进入、点击内部链接、浏览器 Back/Forward、手动 URL 深链、`reduced-motion`、触屏、键盘都使用当前 Next 路由，避免增加容易丢失的临时 UI 状态。世界菜单展开状态为 UI state，不写入经营存档。
5. 调整图像前先独立保留 `gothic-lobby-painting-image`、`gothic-character-talk`、已有四位人物肖像和所有业务 `data-testid`，不因为菜单重构使自动化验收无法对应真实行为。

## 4. 实现前需要对照的视觉稿

**PC 线框**（非正式截图，也不占人物图像像素）：

```text
┌────────玩家 / 四位角色────────┬────────主绘景／月纱────────┬─月蚀活动 + 入口海报─┐
│ 人物头像列表、进度摘要        │   主人公 / 会话热点        │   真实绘景小海报      │
│                              │  （避免按钮穿过脸部）      │                      │
│                              │                            │                      │
└──────────────────────────────┴────────────────────────────┴──────────────────────┘
       底部轻型铜色入口： [公寓] [工坊] [角色] [月光街]   [全部地点 ▴]
```

**交互：** 点击「全部地点」→ 一个以现有七目的地为来源的紧凑世界地图清单；选择「委托」或「仓库」可以立即导航。世界菜单不是另一个大号全屏按钮堆。

## 5. 验收清单（没有真实验收不得写 DONE）
