# R12.2 · 移动公寓房门按需展开

## 问题与证据

2026-11-21 在 GitHub Desktop Visual Review 的 390×844 真实浏览器截图中，公寓的六扇常驻大房门覆盖了女主人肖像的左半边。PR #46 已经修复顶栏按钮截断，然而房门列表仍持续遮住人物。与此同时用户明确要求全屏绘景、角落小型 HUD，以及无需理解六个永久按钮的自然交互。

## 交互规则

- 手机宽度不超过 600 CSS px：初始只显示一个紧凑的「房间 · 当前入住 X/6」触发器，六扇房门默认收起；点击后显示原有六房间列表，绝不删除或改写房间功能。
- 抽屉在点击房间后自动收起；选中房间的既有「建造 / 派住客 / 互动」抽屉仍正常出现。再次点击小触发器或在面板中按 Escape 可关闭；Escape 后键盘焦点回到触发器。
- 若有真实公寓事件，触发器显示事件提示；事件文本仍保留在展开列表里。
- PC 宽度大于 600px：原来的六扇房门一直可见，完全不改变既定 1440×900 构图。游戏场景和人物原画不会因为这项 UI 变更被裁剪或放大。
- 使用已有 React 状态与 Tailwind 组件样式，不引入额外的菜单依赖或第二套路由；不改 Cozy 存档、入住数量、建造消耗、角色身份和自动推进时钟。

## 验收

专项 Playwright 在 390×844 检查：初始房间按钮隐藏、触发器显示真实入住数、展开六个可点击房间、面板不超出屏幕、Escape 焦点可恢复、点击第三间能进入已有房间操作抽屉、关闭后货币仍为原值。随后切换到 1440×900，原六个房门仍是常驻，移动触发器被隐藏。

截图应覆盖两端：`mobile-room-chooser-closed-390.png`、`mobile-room-chooser-open-390.png`、`desktop-room-chooser-1440.png`。在 Gameplay Browser Review 的实际 PNG artifact 内查验，而不以 DOM 通过冒充视觉结果。

这项修复只是把挡住主视觉的可交互层收起来，**没有制作独立公寓/契约大厅/仓库的高清环境图**。S02/S05/S06 的独立高画质双端原画、场景物件锚点和人工商业授权仍由 #16/#24 跟踪，不能因为「画面露出了更多人物」就关闭高清美术任务。
