## 2026-11-02 · P2-A 肖像展示质量修正（不是正式 CG 交付）

### 线上真实问题

部署后的角色图鉴中，泉泡、青枝、炽角为原生 **512×512** 方形肖像，月下誓约是 **930×910** 肖像；旧实现对所有图片统一使用整个细长卡面的 object-fit: cover，导致四张非全身画作在超高画框内左右强烈裁切。月蚀独立候选画稿为原生 **1086×1448**，不等同于正式 1536×2048 的生产 CG。

### 本轮代码修正

- A05 卡片依据已有 CG 审核/预览注册表识别 **独立构图画稿** 与 **普通角色肖像**，不根据角色名假装所有卡都已有全身 CG。
- 只有有独立候选或已审核全身图的卡使用完整画框；为匹配参考图的超窄竖卡，卡片预览采用居中 cover 裁切，完整人物观看弹窗保持 contain，以免把 3:4 原画缩小到竖卡底部。画作仍受 manifest 审核门禁控制。
- 四张普通肖像放进真实 3:4 比例的小肖像框，避免原生 512 方图被强行裁成 1:3 人体展示；框下面是人物契约标识与真实身份说明。暂不把低分辨率图或现成角色截图拼成假的「全身立绘」。
- 保留实装选中、收藏状态、右侧 20 项能力映射、工坊/剧情/房间路由及存档；没有改动抽卡概率或交易。
- 增加浏览器几何检查：确认肖像框宽高比 0.75，卡片预览 object-fit: cover，完整欣赏弹窗 object-fit: contain，并检查五张图片的自然尺寸。

## 2026-11-02 · A05 桌面端构图与真实装备精调

### 根因：全局浮动导航覆盖了参考图导航宽度

线上检查发现全局 `gothic-desktop-ui.css` 的桌面 `body .gothic-dock-bar:not(.gothic-dock--cinematic)` 通过 `!important` 强制把所有普通导航压成最大 **1016px** 浮动小条并把 bottom 固定到 **17px**。A05 的局部 `.cg-dock` 即便设置了近全屏宽度也无法生效，因此底栏明显偏离参考图。这是实际 CSS 优先级冲突，并非图片颜色问题。

**修复**：A05 的唯一 `GothicDock` 增加已有 `gothic-dock--cinematic` 语义变体，从旧全局浮动规则中合法豁免；其他六个世界页面继续沿用原有标准，不新增第二套导航，不通过新的 `!important` 再次覆盖。图鉴局部样式把桌面底栏设置为全宽、离底部约 4% 高度，中央卡片/进度/右侧面板底边按 1672×941 母版重新对齐。

### 内容精细化与真实玩法

- **右侧角色特写**优先使用对应契约已纳入 manifest 的视觉形态：神话月蚀使用现有月蚀候选画稿，与黑发角饰的参考图相符；没有独立卡面 CG 的人物继续使用该居民的正式脸图，不混脸。大幅原画仍非全身正式生产 CG，五卡自身引用 manifest 管控的现有艺术资源。
- **装备**按当前游戏真实模型展示「装备」「首饰」两个槽，不虚构参考图中四个已满 20 星装备。点击槽位会进入现有锻造/装备弹窗，并继续调用真实存档与制作逻辑。
- 卡片下的副标题改为「契约鉴赏 · 人物档案」，不在缺少四张正式全身 CG 时宣称全部是正式立绘。
- Playwright 新增 1672×941 设计坐标断言，检查卡片/进度/详情/底栏的纵向构图和底栏宽度不再退回 1016px；另外检查两装备槽真实存在。

### 尚未交付

独立 A05 紫月教堂/玫瑰/烛台背景和四张全身人物原画尚不具备与参考图完全一致的独立制作源，暂保留已入库过渡场景，不从带 UI 的效果图直接裁人物或背景投入生产。下一步正式美术交付必须先满足独立原画、身份一致、许可与来源审查，再更新 `cg-manifest.json` 生产状态。不得写成已完成 1:1 美术复原。

### 月纱双契约外观一致性

用户批准的 A05 参考图中，神话月蚀为**黑发、角饰、暗红与金色**，月下誓约为**银白发、紫色月光**。这两张是同一名月纱的两种契约形态，不应为了统一基础头像，把神话形态右侧详情误换成普通银发造型；但任何新正式 CG 仍需在角色美术审核中逐项确认眼型、契约印记、叙事身份及图像来源。现有候选只供鉴赏，不可因此自行晋级 `production`。
