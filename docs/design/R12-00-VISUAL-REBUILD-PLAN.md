# R12.0 · 高清美术补齐与首页导航重制执行计划

> 日期：2026-11-14 · 状态：**规划已建档，尚未交付新原画或新首页代码**。
> 触发：玩家反馈「很多图模糊、场景图少、首页菜单不好看」。本计划不是像素实测报告，不把设计方案或 CI 全绿冒称视觉完成。
> 核对基线：功能版 [`6d997e4d`](https://github.com/kunlong-luo/monster-apartment/commit/6d997e4d0b2a8229d989f5643bcd4bc19f311e08) 的 Quality、Desktop Visual Review、Gameplay Browser Review full（166 passed / 2 skipped）与 Pages 同 SHA 成功；随后纯文档 PR #23 已合并，不能把 `be3dc43c` 本身当成重复执行的全量浏览器结果。

## 1. 本阶段目标与不做的事

目标是将 **「满屏场景 + 可识别的人物 + 清晰的空间差异 + 低干扰的游戏导航」** 变成真实可玩页面，而不是为旧结构继续叠加 CSS。R11.3 的成功说明当时已有覆盖的代码功能可发布，**不代表原画像素质量达标**。

- **R12-A / P0：首页画质与菜单**。先定位当前大厅绘景的实际解码、渲染占比、不同 DPR 下的有效像素；在不覆盖人物的前提下设计并实现更轻、可访问的主导航。
- **R12-B / P0：委托／仓库场景去重**。它们当前复用 `v2/art/moon-workshop.avif` 原型；优先制作相互独立的场景候选并审核。公寓公共空间同批列入，延续 [Issue #16](https://github.com/kunlong-luo/monster-apartment/issues/16)。
- **R12-C / P1：月光工坊／月光街的正式环境升级**。当前 1920×1080 过渡绘景只能证明像素尺寸，厅堂不代表生产车间，庄园大门不代表街区商业场景。
- **R12-D / P1：四间人物私室与人物 CG 的分层制作**。现有独立 SVG 为概念，可玩但不是正式高清美术；先制作一间完整背景 + 独立人物层作为质检样板，再复制生产管线，不能直接全部标记 ready。
- **R12-E / P1：七场景一致性与性能验收**。包括图片加载失败、旧存档不变、手机裁切、交互热点、Pixi 渲染清晰度、减少动态效果与深链导航。

本轮**不**重新设计经营数值、抽卡概率、角色身份、存档键、七个正式路由；不做未经批准的商业授权假设；不把通过静态导出的样机图当作正式资源；不以大量 E2E 代替针对画质的真实截图审查。R11.3 的治理 [#9](https://github.com/kunlong-luo/monster-apartment/issues/9) 与十人真实试玩 [#10](https://github.com/kunlong-luo/monster-apartment/issues/10) 保持独立阻塞，不因 R12 文档关闭。

| 月光街 | `world-scenes/town-moonlit-gate.webp`（1920×1080） | 夜间庄园入口，不是具有商店与角色生活的月光街 | P1 |
| 私室 | 四张 `concept-scene.svg`，manifest 四间均 `backgroundStatus=concept` | 概念层不是正式绘景、人物四姿态也未审稿 | P1 |
| 人物图鉴／召唤 | V3 月纱肖像 700×830／半身 930×910、其他角色过渡肖像 | 大卡展示如由小幅头像填充可失真；需逐张验算显示尺寸和候选 CG 审核状态 | P1 |

**必须区分**：文件字节少、`<Image unoptimized>`、1920×1080 与用户感受到的“糊”之间不构成直接因果链。应实测 `naturalWidth/naturalHeight`、DPR、CSS 绘制面积、图片完整性/编码、构图焦点与源图实际细节，再决定是换源图、改缩放、修图还是调整后处理。不要为了硬达到文件体积指标无意义增大图片。

## 3. 场景资产最小生产批次

先做有差异的 **七个世界主场景身份**，而不是把同一张沙龙图裁成七份：

| ID | 目标 | 独立视觉语言 | 首批交付 |
| --- | --- | --- | --- |
| S01 | 大厅 / 月纱主舞台 | 月蚀窗、人物主焦点、右侧活动卡安全留白 | PC/手机双构图高清主绘景 |
| S02 | 公寓公共空间 | 多层走廊、门牌、通往四私室的门廊 | 独立公共走廊绘景 + 热点图 |
| S03 | 工坊 | 真正有熔炉、晶核设备和生产通路的工坊 | 可与 Pixi 机器和 15 格舞台分层的环境 |
| S04 | 月光街 | 可区分的铺面、建筑入口与生活线索 | 街景全景 + 独立手机裁切 |
| S05 | 委托大厅 | 契约桌、印章、公告栏、月色光源 | 不带烘焙文字或按钮的独立大厅 |
| S06 | 魔法仓库 | 清晰货架、晶核容器、收发区 | 独立仓储绘景，清楚区分委托 |
| S07 | 人物图鉴 | 月蚀画廊、肖像展示台、低干扰藏品背景 | 不放大小头像充当全身 CG 的展示空间 |

四间私人房间 **R01 月纱契约会客室、R02 泉泡铜管休息间、R03 青枝叶影温室、R04 炽角炉火修补间** 追加独立 1920×1080+ 背景及独立透明人物分层；先让一间的锚点／人物边缘／桌面和手机截图通过审核，才批量推进另外三间。按 `public/art/rooms/manifest.json` 和 `docs/v3/30-ROOM-ART-STAGED-ADMISSION.md` 审核，不直接改 `production` 字段。

**制作规格（候选门槛，不是当前资产实测）**：
- 全屏 PC 候选目标 2560×1440 以上；长焦点/双屏需求可选 2880×1620；保持真实可用画面细节，不要把小图 AI 放大后宣称原生。
- 手机独立构图 1080×1920，按 `390×844` 安全裁切，不强迫 16:9 图片成为竖版。
- 首屏资源选择 WebP/AVIF，并测低端机加载、文件大小与 LCP；高质量不等于全部无损 PNG。主视觉可根据实际压缩观感设定不同预算。
- 分层：背景、人物、可互动前景、灯光／粒子、HUD；画面**不得烘焙按钮、动态数字、游戏内文字、角色对话**。
- 每个新素材必须保存来源/许可、原始尺寸、输出尺寸、SHA-256、角色身份、PC/手机构图和审核人签署；先 `review`，人工通过才 `production`。
- 新原画不改变已有热点规则；换底图须重新验证 `objectAnchors`、命中区及 `projectCoverAnchor`。

## 4. 执行顺序：每轮都有可见可验收的交付

| 迭代 | 先决条件与实现任务 | 完成定义 |
| --- | --- | --- |
| R12.0.1 · 基线 | 收集七页 PC 1440×900 / 1648×928 与手机 390×844 / 390×550 实机截图，记录实际 URL、原图 px、CSS px、DPR、图片解码、失败回退、卡顿与主观糊点；标出对应源码 | 七页截图与一张带证据的模糊根因表；不把现有旧截图当本轮新审稿 |
| R12.0.2 · 首页导航 | 以 [菜单规范](R12-01-LOBBY-NAVIGATION-REDESIGN.md) 为准整合 `GothicDock` 与互相覆盖的 CSS，做小型可展开世界地图入口、真实焦点与触控；先保持已有大厅参考结构 | 7 路由仍可达、无重复导航、人物展示区扩大；PC/手机按截图与键盘回归通过 |
| R12.0.3 · 首张高保真 | 大厅新 PC/手机背景从候选→人工审查→接入，修复 fallback 与裁切；禁止伪高分辨率 upscaling | 对照旧 V3 主图，新图高 DPR 细节真实改善且无脸部截断；保留原旧图回退 |
| R12.0.4 · 去重 3 场景 | 公寓、委托、仓库分别拿到独立候选图，审核版权与素材层级后依路由接入 | 三页一眼可分、操作面板不遮挡热点、旧存档不变 |
| R12.0.5 · 工坊/街区与私室样板 | 为工坊、街区升级正式环境，再完成一间私室的背景/人物层样板 | Pixi DPR、生产动画、热点锚点、CPU/资源释放、手机都通过；其余私室待逐一审核 |
| R12.0.6 · 全站验收 | 复查七地点、人物图鉴、加载回退、LCP 与导航/资产一致性，结合 #10 真实试玩决定下一批 | **同一 SHA** Quality + Desktop Visual Review + Gameplay Browser Review full + Pages；附人工截图与审稿证据 |

**发布原则**：先在 PR 分支按改动范围做最小可证明的测试；涉及游戏路由或资产表现时跑必要的真实浏览器/视觉审核，发版后核对 Pages。保留稳定库而不为简单图层自写新渲染引擎；动画仅在有必要时用已有 Motion/Pixi，遵守 `prefers-reduced-motion`。禁止 Sparkles 图标，遵守 `DESIGN.md`、`docs/IMPECCABLE.md`。新一轮每次仅解决一个可证明的视觉缺陷，不再追加不可控覆盖层。
