# 月纱新版 HUD 视觉原型保留记录（V3.9）
本目录仅保留审查参考：`yuesha-hud-experiment.tsx.txt` 为单文件 UI 实验稿，并非可玩的正式页面，不能直接发布。

## 未通过游戏准入的原因
- 整张大厅概念绘景本身包含月纱，再叠加非透明立绘会出现重复人像。
- 将 128650 金币、3240 水晶、18 紫晶、亲密度 320/500 等展示为真实货币/进度，实际上全部为静态数字。
- 礼物点击仅修改本地组件 state，不使用人物存档，重新加载即丢失。
- 其他人物均复用月纱头像，假装存在尚未完成的房间与人物。
- 新热点 ID（如 wardrobe、vanity、contract）未加入当前 CHARACTER_ROOM_OBJECTS 的验证清单；新“调查”无法持久记录。
- 未沿用 V3.8 已有的房间演出、线索进度、原生自动剧情和单一人物图层，容易造成回归。
- 大量无实际事件的信箱、设置、商店等按钮不符合“真正可玩”的产品约束。

## 下一步集成准入
1. 美术验收必须拆成**无 UI/无人物纯背景**与透明人物帧，而不是使用原型合成图当底图。
2. 新 HUD 拆成 <GameNav/>、<ResidentSwitch/>、<RoomStage/>、<DialoguePanel/>、<CollectionBar/>，删除房间内重复全局导航。
3. 所有资源展示必须绑定现有的真实经济/人物数据；暂未开发的系统显示“未开放”或不渲染，禁止硬编码假余额与亲密度。
4. 未解锁的角色及故事不能伪装已有进度；礼物应先有实际库存和持久化规则。
5. 复用 V3.8 的场景热点、剧情演出和 V1 存档格式，先通过自动化与手机端视觉检查再设为正式版本。

本次将可玩基线恢复为已通过的 V3.8 组件，不删除新原型设计想法。
