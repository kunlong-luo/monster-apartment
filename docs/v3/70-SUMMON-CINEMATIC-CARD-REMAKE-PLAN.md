## 1. 视觉设计冻结：一个真正的「大卡舞台」

- **PC 1440×900 与 1648×928**：结果页全屏暗化背景；视觉中心放单张人物主卡，建议宽 420–490px、高 610–710px；旁边可用一条细竖栏显示卡名、品阶和状态；十连的 10 张缩略卡使用单排胶片条或低层网格，但始终让主卡占大部分注意力。所有内容必须落在视窗内，无需页面级滚动，不允许底部导航挡住结果。
- **卡内结构**：上缘细金线稀有度徽章，中央人物艺术区域占 70–80%，下缘窄铭牌显示角色名、契约名、稀有度、首次获得/重复以及碎片实际数值；绝不在角色脸/眼睛上覆盖价格、标签或按钮。
- **图片规则**：仅正式审核的 `cardIllustration` 使用 `object-contain` 或按构图标注的焦点裁切；暂用现有 `face.webp` 时标注「肖像展示 / 全身卡面制作中」，限制放大并使用有意设计的肖像构图，不能假称全身高清立绘。现有图鉴和抽卡结果共享人物身份，不交换人脸/发型。
- **效果强度**：主卡清楚优先；金线、红月流光、稀有辉光和粒子只在舞台背景/边框，不盖脸；进入后停留供玩家细看，不自动关闭。
- **稀有颜色**：N 雾银；R 霜蓝；SR 暮紫；SSR 传说暖金；SSR 神话深酒红+赤金。视觉品阶只能从抽出的 `rarity`/卡表读取，不能从“主题池”或人物潜力等级猜测。

## 2. 可执行批次（按先后顺序）

### P0 / V3.70：正确的抽卡结果舞台（最高优先）
**目标：一抽一张大卡，不是十张小头像。**
- [ ] 新建独立的 `SummonResultStage`，在 `SummonRitualModal` 使用；只从 `characters` 已确认结果数组读数据；显示每个 `firstAcquired` 与 `awardedShards`，不得随机生成演出结果。
- [ ] 新建共享 `CharacterContractCard`：角色图像、真实 `rarityZh`、人物名称、契约称号、奖励铭牌；将静态卡框和人物图分层。
- [ ] 单抽默认主卡大图，十连优先显示当前选中的角色大卡，缩略卡可用键盘/鼠标切换；提供“全部查看”且不清掉已揭晓信息。
- [ ] 修复结果页“再抽十次”总是固定文案的问题：单抽提供相应数量操作，十连可再十连，资源不足禁用并反馈；不提供无意义的重复按钮。
- [ ] 统一 `character-summon-reveal.tsx` 的肖像组件，但保留原故事召唤与 Gacha 的不同存档调用路径。
- **验收**：1440×900 无遮挡；N 与 SSR 都能完整看清脸和契约名称，十连全部结果可被选中；不存在 5×2 拥挤的 10 张小卡充当最终展示。

### P1 / V3.71：电影式仪式与稀有揭晓（完成 P0 后）
**目标：真实契约开启，不再是单个转圈月亮。**
- [ ] 采用纯展示状态机 `idle → charge → seal → omen → flip → focus → summary`；React/Motion 控制镜头和图层，已有 PixiJS 负责适量粒子，禁止重复自造动画框架。
- [ ] 参考时间预算：蓄力 0.4–0.7s，封印 0.5–0.9s，品阶预告 0.4–0.8s，卡牌翻面 0.5–0.7s；这是目标节奏而不是无条件等待；高阶可稍长、普通较短。
- [ ] 先出现封印/卡背，之后受控翻面，SSR 金光及神话红月特效只从真实结果触发；抽卡主题不产生“虚假概率提升”提示。
- [ ] “跳过动画”直接进入可操作的真实结果，不触发新抽取；系统 `prefers-reduced-motion` 和游戏内减少特效设置全程有效。
- [ ] 快速连点、关闭、跳过、异常退出必须只扣一次真实资源；持久化已由引擎负责，动画不能写入抽卡/收藏存档。
- **验收**：单抽从蓄力到开卡有分镜；禁动画模式无强制等待；跳过与不跳过所得卡及碎片完全一致。

### P2 / V3.72：十连大卡焦点与高阶停顿
**目标：十连的重点是最高稀有角色，而不是小卡阵列挤在屏幕中间。**
- [ ] 10 张结果按照真实抽出顺序显示，不重排概率，也不额外抽卡。
- [ ] 自动揭晓模式只对已有结果逐张移动焦点；可暂停/跳过；高阶结果单独占中央舞台，不要求用户连续手点十次。
- [ ] 一次十连存在多张 SSR 时，全部都可单独回看；默认焦点可以优先指向最高品阶但不能隐藏其他卡。
- [ ] 缩略图、主卡、奖励明细来自同一份抽取结果对象，不出现卡图与卡名不对应的问题。
- **验收**：出现 10 张图后可点任一张放大、键盘方向键切换、重复契约碎片数量准确；十连 SR 保障不变。

### P3 / V3.73：正式卡面 CG 生产与接入（依素材验收，不强行升级）
- [ ] **5 张正式卡面候选**：月纱·神话月蚀、月纱·月下誓约、炽角·炉火余烬、青枝·春芽誓约、泉泡·潮汐来信。月纱两种契约须有不同的服装、光源与姿态；四张脸型各不相同，均是成年人物。

- [ ] 每张导出 `master`、`card`、`thumbnail` 三个用途；保留制作来源、原创性和商业使用权的审核记录。推荐拟定目录 `public/art/summon/cards/{cardId}/`，但只有审核通过后才写入运行时卡表。

## 3. 组件边界与不得破坏的领域规则

建议拆分：
```text
src/components/summon/
  summon-ritual-modal.tsx          # 现有弹层，负责挂载/关闭与操作分发
  summon-sequence.tsx              # 新：Motion 有限状态演出
  summon-result-stage.tsx          # 新：主卡焦点和十连胶片条
  character-contract-card.tsx      # 新：复用的卡面视觉组件
  summon-card-art.ts               # 新：卡图来源/审核状态映射
  summon-vfx.tsx                   # 新：复用 Pixi/Motion 效果入口
  summon-cinematic.css             # 新：少量专用样式，与旧 CSS 逐步合并
```

- 领域数据 `executeSummon` 仍是唯一真正抽取入口。返回 `characters` 的一次性结果快照后，动效读快照，不调用随机数补演出、不再次触发抽卡。
- **N46%、R31%、SR17%、SSR Legend5%、SSR Mythic1%，90 抽 SSR 保底、十连 SR+** 是既定规则，完整保留；多个卡池目前只是不同主题画面，抽卡概率一致，不得误称 UP。
- 既有 `monster-apartment:gacha-v2`、`character-collection` 持久化结构保持兼容；首次/重复/碎片均展示真实引擎字段。重复抽到的角色不要出现“新角色”提示。
- 借用成熟 Motion、PixiJS、Lucide、Next/Image；不要为翻牌或光效另装沉重依赖。只有确有独立材质必要时才评估动画依赖，先衡量许可证、包体积与静态导出兼容性。
- 开发直接基于主分支，提交有玩家可见的改动，每一批明确标注「已写代码 / 质量通过 / PC 实测 / 线上已部署」，不可把文档提交当成游戏功能完成。
