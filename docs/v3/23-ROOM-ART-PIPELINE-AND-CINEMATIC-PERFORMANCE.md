# V3.6 · 私室演出与正式美术资源契约

## 本轮实现

- RoomSceneBackdrop：建筑背景纹理保持固定，不做帧间缩放或模糊；烛光、月光束、浮尘为独立可关闭的动画层。
- RoomResidentSprite：人物有 idle / attentive / warm / guarded 四个表演状态，按调查和话题变化。当前是现有高分绘景的动态演出，**尚不是真正的四套表情帧**。
- RoomDialogueTheater：自由交谈可进入场景内的剧情镜头，台词自动逐句播放；后台标签暂停、支持跳过和退出，减少动效时立即显示完整文本。
- 移动端进入演出时自动定位到上方场景，不新增路由，不改变角色、公寓、工坊存档。
- 表演规则在 src/core/room-performance.ts；纯美术合约在 src/core/room-art-manifest.ts。

## 分层资源规格（严格顺序）

1. 背景（静态建筑）：建议 2560×1440、最低 1920×1080，sRGB WebP。只能包含建筑、家具、月光窗、茶桌、蜡封、旧书等陈设；严禁把人物、功能栏、文字、数值或热点画进底图。
2. 氛围：独立烛光、月光束和漂浮微粒，透明且不能截获点击，游戏内和系统减少动效时停用。
3. 角色：透明 RGBA，推荐短边至少 1200px；idle、attentive、warm、guarded 姿态使用相同画布与脚点，不允许画进背景。正式眨眼与口型必须交付真实逐帧素材才可宣传为多帧。
4. 物件：蜡封、茶杯、账簿等必须与 room-stage-layout.ts 热点锚点一致。真实交互由 DOM 按钮承载，不得伪造图片按钮。
5. 剧情：自动镜头作为独立层，只依赖已有话题解锁规则，不变更剧情选择及经济数值。

资源目标目录：
- public/art/rooms/{id}/background.webp
- public/art/rooms/{id}/poses/{idle,attentive,warm,guarded}.webp

目前 room-art-manifest.ts 的 status=concept；仓库继续使用临时大厅绘景与现有角色素材。未制作合格背景和透明帧前，不可切换 status=production 或请求不存在的路径。

## 验收与品质边界

- 不能把带 UI、角色的参考合成图直接用作室内背景。
- 需要确认透明边缘无白边；390px 手机和宽屏均保留主要道具；热点最小 44×44；工匠值守时不在私人房间重复出现。
- 制作素材时必须记录授权来源并审核质量；不能使用不明版权第三方裁图。
- Vitest 检查逐句拆分不丢失文字、姿态映射与资源声明；Playwright 检查自动播放、跳过、关闭、减少动效、移动端、存档不变；继续执行七页面健康检查、静态构建及 Pixi 审核。

第一优先美术资产是月纱契约会客室的无人物原画：深紫丝绒、香槟金烛台、哥特月窗、旧契约、蜡封和茶具；角色留右侧独立表演区。所有正式画面在单独验收之后再替换目前的概念素材。
