# V3.1 角色对话与叙事交互 PRD

> **状态：Planned / 尚未实现。** V3.1 聚焦「剧情对话驱动 × 自动经营支撑 × 高品质 CG 收藏 × 关键动画演出」。与 [主线剧本](05-MAIN-STORY-SCRIPT.md)、[收藏系统](09-CG-COLLECTION-AND-ART.md)、[伏笔和彩蛋](10-FORESHADOWING-AND-EASTER-EGGS.md) 配套。

## 1. 核心体验与边界

玩家因人物和故事而留下，因新回忆插画而期待下一段剧情，用有代价的经营配置推动剧情条件，关键高潮以高质量演出增强情感。**对话不是让用户机械点五十次继续，特效不是靠永远在播的粒子填充屏幕。**

- 对话是「经营发生之后的回应」，而不是凭空弹出用来拖延时间的文字。
- 工坊自动生产、物资运输、订单与公寓生活在玩家阅读对白时仍按真实规则推进；仅玩家显式暂停经营才暂停。
- 叙事优先采用高质量静态分层插画 + 表情、眼神、镜头、局部动作，不承诺每句对白制作高成本逐帧动画。
- 关键剧情首次触发演出，重看允许选择跳过、静态模式和字幕回顾，奖励仅通过唯一领域事件提交。
- 可选探索彩蛋不能变成主线通关必要条件。隐藏剧情应回收伏笔、深化角色，而不是制造不可逆错过。

## 2. 两种叙事模式

| 模式 | 触发 | 画面布局 | 长度与交互 |
|---|---|---|---|
| 轻对白 Ambient Banter | 泉泡开工、青枝提醒、街道恢复、访客到达等已确认事件 | 场景内小气泡/头像，不截获 Pixi 地块点击 | 1–2 句、可收起、频率限制；不自动推进剧情 |
| 正式剧本 Story Scene | 主线、支线、玩家主动打开新事件 | 沉浸式背景、人物立绘、下方安全区对话、2–3 个有意义的选项 | 通常 30–120 秒；支持逐字/整句、自动播放、重看、跳过已看 |

**首次序章**可主动引导玩家，但必须提供明显的跳过和恢复入口。非强制剧情通知只显示一个紧凑入口，玩家可先继续经营。每章正式对话数量受限：优先新增有冲突和回报的场景，不为填充时长增加独白。

## 3. 主要界面规范

**PC（建议 ≥1024px）**：全屏游戏绘景可见，不糊背景；单角色时立绘占安全宽度约 35–45%，双角色不挡住对白，当前发言者高亮。底部字幕区采用半透明材质，显示姓名、文本、角色表情与继续指示。左上小型返回/回顾入口，避免一圈大按钮。

**手机（320–430px）**：人物展示区域独立缩放裁切、重点保留脸部和手势；字幕底部避开 safe-area 与导航 dock；每个选择触控区域至少 44px；文字可换行，无强制横向滚动。可在选择状态时收起部分立绘让出空间。

**控制**：继续、自动播放、跳过已看、历史对话、音量/静音、字幕速度、减少动态效果、恢复上一次可安全重开的场景。跳过至选项不能自动替玩家做重大决定。

**可访问性**：键盘 Enter/Space 继续，Esc 关闭可选剧情；对话使用 aria-live 或明确朗读区域，不依赖特效和音效传达信息；用户关闭自动播放后不应被页面切换重新打开。

## 4. 剧情状态机与选择语义

`locked → available → queued → playing → choice-pending → resolved → watched`。

- `available/queued` 来自剧情前置条件与领域事件，不是靠 UI 点击次数。
- `playing` 的文本进度、角色表情属于可重建显示状态；玩家可关闭并从最近句子恢复。
- `choice-pending` 必须保持直到用户确定，重大经营选项要展示资源缺口/预计订单损益。
- 选择提交应有 `sceneId + choiceId` 唯一去重键，写入故事状态后更新收藏解锁；不得因为双击或重新打开重复扣库存/加好感。
- `watched` 回忆模式只读，不能反复领取好处；选择回放展示历史选择而非重新投票。
- 生产事件在读对白时发生可以排队提示，但不能突然中断当前剧情；奖励依据事务确认而非演出结束。

## 5. 台词编排与人物声音

角色按照 [人物圣经](04-WORLD-AND-CHARACTERS.md) 表达：月纱谈判、反问与留白；泉泡短句与「咕噜」；青枝透过植物观察世界；炽角短促有力；阿洛精确；菲娅温柔而坚韧；伊索务实；诺因谨慎而有逻辑。

- 单句建议 10–40 个中文字；节奏先看见异常 → 人物作出反应 → 给玩家选择 → 经营或世界产生变化。
- 情感线可有亲密、信任、遗憾和幽默，但人物首先是有职业、意愿和人格的个体，不用露骨性内容代替人物魅力。
- 「留白」通过表情、镜头和两秒环境声完成；不为每个标点做夸张动画。
- 选择至少改变一句后续对白、某项有成本的决策、信任/路线证据或收藏注释；两个同义的「好」不形成分支。

## 6. 剧情数据与渲染分离（建议协议）

```ts
type DialogueLine = {
  id: string; speaker: string; text: string;
  emotion?: 'neutral'|'happy'|'concerned'|'angry'|'shy'|'reflective';
  portraitKey?: string; voiceKey?: string; cueKey?: string;
};
type DialogueChoice = {
  id: string; label: string; nextLineId: string;
  effects: Array<{kind:'relationship'|'route'|'flag'|'policy'; key:string;value:string|number}>;
};
type StoryScene = {
  id: string; chapterId: string; requiredEventIds: string[];
  location: '/'|'/apartment/'|'/workshop/'|'/town/'|'/orders/'|'/characters/'|'/warehouse/';
  backdropKey: string; lines: DialogueLine[]; choices: DialogueChoice[];
  collectibleRewardId?: string; cinematicId?: string;
};
```

这些是**建议接口**，未添加到实际源码。正式实现须以 schema 进行校验，所有分支有可达的末端，选项 effects 进入可信世界 reducer，而非交给 React 直接增减经济数值。

## 7. 情绪与演出层级

- **L0 日常**：姓名、单句、轻微表情变化，不强制镜头。
- **L1 人物**：立绘表情切换、背景灯光、局部视差、少量原生音效；例如青枝发现花斑。
- **L2 重大抉择**：镜头景别变化、合同/钟楼道具特写、完整角色插画；例如月纱旧合同揭晓。
- **L3 章节高潮**：独立 Story CG/分层镜头及独特光效和音乐；例如东街重燃、黑雾、月心灯修复。

不要把 L3 特效当成一条每分钟重复的流水线特效；设备本身只使用状态正确且低成本的循环动画。

## 8. 内容与 QA 验收

- 在玩家第一次看到月纱之前，不允许图鉴完整展示她的旧合同秘密。
- 非关键对白不打断自动生产；切页、重载、睡眠恢复后对话/工坊状态一致。
- 读完场景、跳过已看、回看、快速双击、两标签并发，收藏及奖励最多一次。
- 320/390/820/1280/1920px 下，文字、姓名、选择与退出按钮不重叠；原画不会因多次进出大厅而模糊。
- 视觉特效关闭/图片降级/音效失效时，剧情仍可读可完成；缺少 CG 不得导致主线软锁。
- 对话内容校对：人物称呼、伏笔、道具位置、时间顺序与 [伏笔表](10-FORESHADOWING-AND-EASTER-EGGS.md) 一致。
