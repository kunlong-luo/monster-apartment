# V3.0 自动生产与离线经营 PRD

> **Status: Planned / 非当前实现。** 当前 `runShift()` 为一次点击推进一日的确定性引擎。本文件明确如何迁移为真实时间自动生产，不允许直接按秒循环调用旧 `runShift()`。

## A. 玩家故事与验收标识

- AP-01：首次安排工匠后，机器自动启动，30–60 秒内看到实际产量，无需手动结算班次。
- AP-02：工匠待派工或设备缺料时正确暂停计时，有可操作的原因。
- AP-03：原料从真实相邻设备/库存扣除，不跨格凭空生成；入库、预留与交付不能重复消费。
- AP-04：跨页离开工坊后计时持续；刷新与 8 小时内离线恢复不漏产、不刷产。
- AP-05：多人（多标签页）同时打开同一存档，最多一个写入者结算同一生产事件。
- AP-06：画面/声音/动效均是模拟结果的只读投影；禁用动效不影响生产。
- AP-07：已存在的 V2 设备、员工、库存、订单可以安全迁移，无重置，无无限罚款。

## B. 初步平衡表（提案，等待游戏内测）

| 设备 | 基础产出 | 基础周期 | 原料 | 节拍与状态 |
|---|---|---|---|---|
| 水汽泵 well | +2 水汽 | 30 s | 无；需要工匠和空余储位 | 冒泡、阀门运动 |
| 孢子温室 garden | +2 孢子 | 45 s | 消耗水汽 1 | 叶片摆动、孢子飘落 |
| 晶核熔炉 kiln | +2 晶核 | 60 s | 消耗孢子 2 | 炉火、锻打火花 |

**重要**：这是一套新周期设计，不等同 V2 的「熟练工匠 + 等级」每班产量。升级/专业匹配先改变周期或批量产出中的一项，另一项应有限封顶，避免指数爆炸。周期最短建议 12 秒，产量上限在平衡测试后定。初始仓储/储罐上限需单独标定。

## C. 调度器与权威模拟

### C1. 单一时间轴

- 所有生产状态使用**整数毫秒时间戳**（如 `nextFinishAt`），纯函数接受 `nowMs`、世界快照和命令。
- `setInterval` 或 `requestAnimationFrame` 只负责请求渲染/唤醒调度器，**不直接决定产量**。
- 当设备启动/恢复：检查工匠、相邻输入可用、仓库空间与电力状态。足够时**预扣**当前批次原料，写入唯一循环 ID 和 `finishAt`；否则停在可解释的阻塞状态。
- `nowMs >= finishAt` 时仅结算一次：增加对应产物、释放预留产能、记录审计事件，随后尝试启动下一批。
- 每次完成事件按 `finishAt` 升序、同时间按机器格子 index 升序执行，避免页面/机器遍历顺序改变结果。
- 搬迁、拆除、换工、暂停时不能无成本复制在制品；必须指定中断策略：**取消生产退回尚未消耗的预扣原料**，但已完成出货不能退回；中断造成的真实损耗在以后单独设计。
- “已开始循环”与“缺料停机”不可共存；设备可从 idle → startup → running → output → idle/running；blocked/full 暂停；动画相位绝不改变领域状态。

### C2. 时间与经济隔离

- **真实时间**负责机器生产与物料转移；**游戏章节/剧情日历**由主线事件与经营进程推进，不对每个生产事件触发一次“过去一天”。
- V2 `runShift()` 的普通订单截止日、月纱限时、罚款逻辑不得按真实秒周期原样重用。把 `projectMachineProduction` 中的物理路由规则复用/重构为 `simulateProductionUntil()` 里的每次批量生产。
- V3 订单模型需要 `required`、`reserved`、`status`、`deliveryMode`；有经营时限的订单使用单独定义的**活跃营业时间**，离线期间暂停逾期倒计时（详见 E），不允许扣几十次违约金。

### C3. 机器状态的稳定语义

| 状态 | 发生条件 | 自动恢复 | 可视化 |
|---|---|---|---|
| idle | 未派工/手动暂停 | 派工/恢复 | 环境灯微弱 |
| startup | 有工匠/原料/空间，启动批次 | 启动演出结束 | 灯光升起、机械启动 |
| running | 生产批次有效 | 完成进入 output | 水泡/孢子/火花 |
| blocked-input | 需要的原料不足或断开相邻连接 | 输入到达且空间可用 | 机械停转、明确缺哪种原料 |
| blocked-output | 目标储位满或订单预留限制 | 收货/扩容/调整政策 | 黄灯、停止投入原料 |
| resting | 工匠排班休息 | 休息结束 | 角色走到休息区、机器安全停机 |
| output | 批次已实际落账 | 演出结束后判断下一批 | 可追溯材料流动、产量数字 |

“故障”不是随机扣产量按钮：后续如加入维护/耐久，需要实物成本和可恢复策略；P0 不引入随机损坏。

## D. 仓库、订单与策略

### D1. 每个资源的真实库存

资源存放在唯一账本中：`onHand`、`reservedByOrder`、`inProcess`、`free`、`capacity`；不允许 UI 自建临时余额。统一守恒式：

**可用量 = 账面库存 − 所有有效订单预留 − 在制品预扣；且任何量均为非负整数。**

预扣是否仍计入 `onHand` 必须统一约定：推荐`onHand`代表物理在库，**预扣即从在库扣出并记在制品**，则`free = onHand - reserved`，不可对同一原料二次扣除。

### D2. 交付

- 普通订单默认自动接受和自动交付；达标即写入唯一交付事件，扣库存、到账一次并更新剧情。
- 月纱特别委托必须主动接受；高额奖励需要玩家看到风险；拒绝不扣钱、不关闭主线。
- 公共街灯修复有明确的资源预留（例如晶核 6）；玩家可提高/降低优先级，但**已承诺并出货的晶核不能追回**。
- 订单竞争顺序：紧急且已接受的公共安全修复 → 玩家锁定预留 → 普通自动订单 → 特别委托 → 商人销售；可在 UI 设置，默认策略保护剧情必需资源。
- “自动交付”仅在库存可用、订单有效、目标未完成、事件 ID 未写入时发生。完成演出从结算事件读，不从播放状态写奖。

### D3. 离线产能上限与后台情况

- 关闭/离开浏览器后，首次恢复将最近 `lastSimulatedAt` 至 `now` 的差值限制为最多 **8 小时**；多出的时间不计算生产，**不补连续逾期罚款**。
- 后台标签页节流没有关系：恢复时按时间差进行纯函数补算，不依赖浏览器定时器准确性。
- 输入缺料/仓满后的时间不能“借给未来”：中途停工就停在该点，生产需等待输入实际到达。
- 持续收益不可越过自然容量；离线最多保留有限批次与资源瓶颈，不累计无限生产。
- 防止用户本地设备时钟逆跳：`now <= lastSimulatedAt` 不生产；大幅跃迁记录可诊断信息并执行 8h 上限。**纯本地游戏无法防止恶意改时作弊，不承诺防作弊。**

### D4. 多标签页与原子性

- IndexedDB 是未来 V3 权威持久层；一个明确的事务完成「读取当前版本 → 验证事件 ID → 执行模拟 → 写入新版本」。
- Web Locks API 可用于同源单写者协调，但必须有 IndexedDB 事务/版本冲突处理，不能只依赖一个内存布尔值。
- `localStorage` 旧 V2 键在迁移前只读；迁移后写入 V3 单一事务存档，再把 V2 留作只读回退，禁止双向不同步写入。
- 同一输出循环、订单交付或剧情解锁的 eventId 幂等；多标签同时争锁只能有一个成功事务。
- 崩溃后恢复能检查进行中的事件与 `lastSimulatedAt`，重复调用 `simulateUntil(world,now)` 不会追加相同事件。

## E. 存档迁移规范

1. **读取优先级：** 已验证 V3 存档 → 经过校验的旧 `monster-apartment:workshop-v2-lab` → 新游戏；公寓另按旧 `monster-apartment:cozy:v1` 读取。
2. **不可破坏：** 旧 V2 的工匠岗位、设备位置/等级、储料、现金、晶核、已完成订单数、已接受月纱合同及剧情里程碑，均以能映射的语义保留。
3. 旧 V2 保存的一次性 `last` 班次只作为历史记录，不自动重播、不当作首次 V3 实时事件。
4. V2 剩余“几天到期”的合同须转换为安全的待审核状态或等效**活跃营业时间**，让玩家确认后再继续；不能读成过去时刻立即违约。
5. V3 新设备时钟从**迁移完成时间**开始；不能以首次进入 V2 的时间补产。
6. 先在内存中 `migrate + validate + dryRun`，成功后做一笔 IndexedDB 原子写；失败记录错误并保留原始 V2，不要默默重建。
7. V3 存档带 `schemaVersion`、`revision`、`lastSimulatedAt` 和迁移来源；V3 数据不可覆盖成旧 V2 JSON。
8. 公寓与工坊余额仍为两种独立系统；V3 剧情解锁记录另建世界状态，不做隐式货币转换。

## F. 业务与视效集成

- 累积产量、库存、订单状态进入 Zustand 的统一只读订阅；纯模拟与存档提交不属于 React 或 Pixi。
- Pixi 一次接受一批 `FactoryEvent[]` 演出：`cycle-start`、`consume`、`produce`、`route`、`blocked`、`delivery`。掉帧不补渲染所有粒子，只快进到最新状态。
- 角色工作动作由对应设备与工匠状态决定；不靠无条件永远播放的精灵浮动。
- 允许玩家全局暂停视觉动效、减少动画或关闭音效，但不改变经济时间轴（另设**显式暂停经营**开关）。
- 运行时长 > 20 分钟不应累积永不销毁的 ticker、粒子或 WebGL 纹理。

## G. 可测例子与验收

- 自动水泵每 30 s 产 2，温室每 45 s 消耗 1 水产 2，熔炉每 60 s 消耗 2 孢子产 2。首轮完成时点根据**批次启动/原料到达的真实时间**计算，不可用 60 s 一次性发放所有产物。
- 两台温室争同一水源，必须按统一顺序消耗，不能双双拿到同一份水。
- 仓库容量只有 4 晶核、当前 3 且熔炉下一批出 2：要阻塞或保证不溢出，不能丢货或写成 5。
- 两标签页在同一 2 小时区间同时恢复，事件只有一份，钱和订单仅结算一次。
- 切换七页、刷新、强退后恢复、离线 8h+、设备改岗/拆除/满仓、改系统时间、减少动效模式的规则测试全部通过。
- **回归旧 V2 fixture：** 第一单、第五单、月纱未接/已接/逾期、缺料、三种设备等级、两种存档共存。
- 不通过以上测试，不替换「开始一天生产」入口；V3 可在可回滚开关下先灰度自动生产。

**明确未决项：** 设备容量初始值、专业技能加成、仓满时批次暂停还是禁止启动、订单活跃营业时间的精确规则、模拟事件压缩策略，需 P0 实验数据确定并记录 ADR。不得让策划数字隐性成为硬编码承诺。

## H. V3.3 装备锻造与自动产线的资源连接（待开发）

新增锻造台是已有**水汽 → 孢子 → 晶核**的一个高级消费分支，不能绕过 `simulateUntil` 生成免费的装备和原料；先完成本 PRD 的 P0 权威库存、原料路由、订单预留与多标签事务，再接锻造订单。

- `CraftOrder` 与机器批次共享真实时钟、单一权威事件和 8h 离线封顶；动画不是经济结算器。
- 公共街灯安全预留和已接受合同优先被履约；锻造请求必须显示与公共/普通订单的材料冲突，用户可明确调整优先级。
- 工匠唯一：炽角若被分配到锻造台，则同一时刻不能在别的熔炉算一次额外产量。锻造工艺可作为熔炉同一共享队列的高级 recipe，避免双工位分身。
- 装备产物属于独立可追踪物品实例仓，原料预扣、工单完成、实例入库原子化；改房间/换页不额外生成。
- 角色六维和装备只以有上限的职业效率修正读取设备参数，**不能反向把视觉速度当产能倍率**；更多详见 [17](17-CHARACTER-ATTRIBUTES-AND-POTENTIAL.md)、[18](18-EQUIPMENT-FORGING-PRD.md)、[19](19-EQUIPMENT-RECIPES-AND-ART.md)。
