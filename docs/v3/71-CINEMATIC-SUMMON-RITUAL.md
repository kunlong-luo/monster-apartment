# V3.71 · P1 电影式契约召唤仪式

## 已落实
- 用纯展示有限状态机 `charge → seal → omen → flip → reveal` 取代单一 1.75 秒月亮转圈。每段 620/780/790/1150 ms，单抽和十连沿用同一演出，实际结算由原有 `executeSummon` 在打开弹层之前完成。
- `SummonRitualSequence` 是可独立维护的 React/Motion 演出场景：契约月盘与粒子汇聚 → 锁链封印展开 → 基于**已保存结果里最高稀有度**的品阶预告 → 3D 契约卡翻面 → 完整人物大卡。镜头/动画使用 Motion，轻量符文由 CSS 绘制，不引入额外动画依赖。
- N 雾银、R 霜蓝、SR 暮紫、SSR 传说暖金、SSR 神话深酒红。十连取最高稀有结果只作为演出，不更改抽取顺序、卡表权重或实际保底。
- 仪式每段均可一键「跳过仪式」到 V3.70 的可操作真实结果。系统和游戏内减少动态效果均跳过全部中间状态；关闭、Escape 与跳过只控制显示，不再抽卡。
- 不改变已有 5 档概率、90 抽 SSR 保底、十连 SR+、碎片奖励、七个正式路由、存档键与资源扣除。
- 新增纯函数 Vitest 检查状态进度和稀有预告，Playwright 增加 1440×900 高稀有预告、翻卡过程、降低动态效果以及关闭后只扣一次。
- 五张独立 3:4 全身高清卡面 CG 仍为 P3 美术任务。当前翻面使用独立人物肖像过渡图，不把现有小像扩大称作正式全身图。

## 实际验收
运行 `Desktop Visual Review` 和日常质量构建；只在截图审核通过且 GitHub Pages 成功时宣称上线。

## 首轮实机审核修正
第一次 Playwright 显示 7 项通过、1 项失败：翻卡阶段 `data-ritual-phase=flip` 已切换，但原 `AnimatePresence mode="wait"` 还在等前一个镜头退场，导致翻卡画面可能完全错过。已改为 `mode="sync"` 使翻卡立即挂载，翻卡阶段延至 1150ms，并将装饰粒子改为明确的内联坐标而不是无效 CSS 数学表达式。重新按 1440×900 截图验收。

## 实际截图二次构图修复
浏览器第二轮已 8/8 通过，但人工查看 omen 和 flip 截图发现圆环下缘/翻面卡下缘压到标题。改用镜头专用的绝对布局区：上方独立绘景舞台、中下方标题区、底部进度和跳过按钮；为 omen/flip 添加真实像素几何断言，避免只靠「可见」而再次漏掉遮挡。

## 第三次几何诊断与修复
上一次实际浏览器测出 omen 元素下沿 815px，而文字上沿 642px，遮挡严重；单纯改 art top 百分比不能解决。原因在于 centered Grid item 的 `height:min(100%,810px)` 存在循环百分比高度计算，容器没有拿到稳定的视口高度。已用 `height:min(810px,calc(100dvh - 40px))` 锁定舞台参照（移动端扣减 12px），再维持上下独立分区。增加 `ritualViewport.height > 690` 检查；SSR 预告延至 1250ms，确保玩家能看到高稀有信息和预兆动画。

## 继续定位百分比高度问题（桌面几何回归）
最新截图检查仍记录 `omen.bottom≈814px`、`copy.top≈643px`，说明普通 `position:absolute` 并未可靠锁定动效层。为避免其他容器布局或 Motion 阶段退出影响，把**仅仪式期间**的法阵、文字、进度条改为固定视口坐标布局；正式结果页仍是原 V3.70 布局。测试额外验证演出图层 computed position 为 fixed，再判定实际元素无重叠。

## 修复根因：Portal 解绑页面变换容器
之前调整容器高度与 fixed 像素仍无法保证 omen 元素在文字上方；检查发现全屏模态层原本嵌在游戏界面的有变换/裁剪祖先内，`position:fixed` 的参照与预期视口发生偏差。改为与已有 `CharacterSummonReveal` 一致，调用 React `createPortal` 挂载到 `document.body`。通过 `useSyncExternalStore` 处理 SSR 与初次 hydration 的一致性，弹层挂载后恢复聚焦；动画仍只读取已抽到的真实结果。
