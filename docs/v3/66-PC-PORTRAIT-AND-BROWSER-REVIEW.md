# V3.66 · PC 肖像清晰度与实机浏览器审核

## 从项目资源核查得到的事实

- V2 工坊机械和月光街的旧 AVIF 静态预览仅约 3KB，长期放大成 PC 卡片/绘景无法获得丰富细节。
- 仓库已有四位成熟画风的人物头像 WebP 与月纱的高分辨率人物肖像，但部分页面仍然使用小型 worker canvas 或旧 AVIF 做照片。
- 目前四间私人房间 `public/art/rooms/*/concept-scene.svg` 为概念资源；`productionAssets` 指向的正式 `background.webp` 与透明人物帧均未进入仓库，不能宣称四间已完成高清生产绘景。

## 玩家可见改动

1. 工坊的泉泡、青枝、炽角派工头像接入对应的独立 WebP 肖像，避免使用低清工位小人的缩放替身；工位、派工、工作动画和选择状态逻辑不变。
2. 设备类型标识由字体符号转为 Lucide 图标，和工具按钮同一尺寸/线宽。
3. 月光街内页绘景改用仓库现有的高清世界封面，街区向导改为月纱 V3 高清肖像。全屏背景针对月光街使用已有的独立 V2 绘景，其他地区不变。它们是现有素材的复用，**并非新制作的专属月光街建筑 CG**。
4. 共用资源计数胶囊的天数/幸福度/入住图标使用 Lucide，不再依赖一些字体缺失的符号。
5. 公寓六扇房门按真实住客身份显示细微颜色差异，不添加新的菜单或占用人物绘景。
6. 桌面端新增独立 `Desktop Visual Review` 工作流，在相关 PC 组件变更时跑 1440×900 的两组 Playwright 冒烟并上传真实浏览器截图；与正常 Quality / Pages 解耦，**不作为部署门槛**。

## 限制与下一步

- 独立房间概念 SVG 不能通过 CSS 就变成正式高分辨率 CG。下一轮应生成并审核四幅彼此独立的房间场景，再提交 WebP 并将清单状态从 concept 提升为 production。未经图像验收不得直接修改标志位。
- 设备卡片的旧 AVIF 仍需要独立设备高清绘景资源，不用放大过滤器冒充成品。
- CI 的静态编译通过不等于实机 UI 已通过；需看 Desktop Visual Review 的结果与截图后再做下一次布局修复。
