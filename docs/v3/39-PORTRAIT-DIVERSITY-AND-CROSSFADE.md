# V3.17 · 四姿态视觉差异与平滑替换

## 解决两处实际问题

1. 人物叠层通过 Motion 在 240ms 内淡变。旧版本审核面板一更新图片就撤销旧 Blob URL，导致慢速手机端的旧帧在退出动画结束前失效。本轮在角色图替换或清空时保留旧 URL 500ms，页面卸载仍撤销所有 URL 和定时器，不写入浏览器持久化存储。
2. 过去只比较四张 WebP 的 SHA-256。复制同一姿态、改几个像素就能绕过。现在 `checkPosePixels` 对真实 Chromium 解码的 128×128 alpha 和亮度采样执行两两视觉比较。轮廓差异与共同可见区域的色调差异都很小的帧被拒绝，阈值分别为 0.018 和 0.035。阈值只是排除近重复，不代表真人审核通过或保证美术造型一致。

## 当前素材真实状态

生成尝试仍只得到多人物设定板，而不是无背景的四张独立角色 WebP，因此没有向仓库提交或准入不合格图片。四间角色房间的存档、物件线索与普通玩家布局没有改变。

## 验收

Vitest 校验重配色克隆帧、不同人物轮廓与错误尺寸；Playwright 验证本机透明角色替换时旧图在退出动画期间仍能加载，500ms 后释放。所有新验证和脚本必须经过本轮 CI 才能判断可发布。
