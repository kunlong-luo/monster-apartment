# V3.63 · 首次加载最终兜底与新版本可见性

## 实际修复
- 欢迎页移动端 `picture/source` 对请求失败仅重试一次，连续失败后移除失效的移动 source；最后改用已在仓库中的独立 `lobby-hero-v2.webp`。旧版本用已失败的移动封面作为最终 fallback，不能真正兜底。
- 保留 Next.js Image / `ReliableImage`，不额外引入图片依赖、不增加轮询/全页刷新。
- 发布清单 `public/release.json` 与 `GAME_UI_RELEASE` 一致。客户端仅在初次进入或用户重新聚焦标签页时（15 秒内最多检查一次）读取 Pages 清单；仅发现**更新版本**才在画面边角显示一个「更新画面」操作，**绝不自动刷新**中断游戏；无新版时无按钮。
- 保留原七个路由、屏幕中央角色绘景、角落 HUD、存档键不变；不调整抽卡概率。
- 同步适配现有 Playwright 版号断言和新增 numeric-release / manifest 轻量单测，日常 CI 继续无需完整 E2E。

## 部署与验证
- GitHub Pages 的 `/monster-apartment/release.json` 随静态导出发布；子目录由现有 `siteAssetUrl` 处理。
- 如需看到首次效果，请检查手机移动网络首次访问（包括图片确实失败时的降级）：本次提交不能替代真实移动设备弱网验证。
- 此检查器从 V3.63 开始生效：此前已打开且仍在运行 V3.62 的标签页无法追溯加载新组件，第一次需要用户手动刷新，此后新版本能在标签页重新激活时提示。
