# 七场景统一导航 · 大厅主导航 + 场景快捷地图（2026-11-04）

## 用户反馈与修正决定

用户发现每个页面底部菜单的位置、大小、显隐都不断变化，视觉像管理后台，挡住人物与场景。之前 V3.21 “全部页面固定七入口 Dock”规则在此更新为：

**大厅是唯一显示完整七目的地底部 Dock 的场景**；公寓、工坊、角色图鉴、召唤子视图、月光街、委托和仓库不再常驻七按钮底栏。所有子场景使用 `RootLayout` 统一挂载的 **左下角小型「大厅 / 地点」入口**。这不是删除世界导航，而是默认折叠、需要时直接展开七个正式目的地。

这个改动来自用户主动提出的导航改造，而不是擅自偏离此前 A05 图像。A05 原参考图的底部 Dock 作为早期视觉基准保留；新交互要求明确优先于该局部视觉元素。中央人物卡获得原底部条所占空间。

## 参考范式（不是逐像素仿造）

- [《明日方舟》首页](https://arknights.wiki.gg/wiki/Home_Screen)：主菜单集中承担角色、招募、基地、仓库等功能入口。
- [《原神》快捷轮盘](https://genshin-impact.fandom.com/wiki/Shortcut_Wheel)：主要功能可以按需呼出，代替持久在线屏幕的大型菜单。
- [《剑与远征：启程》菜单](https://afk-journey.fandom.com/wiki/Menu)：游戏内用独立菜单入口管理大量功能，保留场景空间。

由此选择 **“大厅显式 + 子场景隐式”混合型**；不采用所有场景都出现全宽导航，也不采用只能先回大厅再跨页面的反复跳转。

## 唯一数据源与 UI 所有权

- 所有目的地仍只来自 `src/components/moonwork/world-navigation.ts`：大厅 / 公寓 / 工坊 / 角色 / 委托 / 探索 / 仓库，七条正式路由不增不减。
- `GothicDock` 只用于大厅，`activeHref='/'`；其他页面的旧调用兼容性地返回 `null`，逐步清理旧页面调用及无用 Dock CSS。
- `app/layout.tsx` 放置唯一 `GameSceneNavigation`；其入口恒在画面左下角，避免每个场景单独定义样式和位置。
- 子场景默认只显示两个极小控件：「大厅」直接回大厅；「地点」弹出世界导航。菜单从上方展开且有当前场景、7 项简述和 `aria-current=page`。
- 点击菜单目的地直接进入目的页面，不能强制返回大厅中转；`Esc` 关闭菜单并让焦点回到入口，点击菜单外关闭。
- 有 `aria-modal=true` 的原画鉴赏、角色房间、召唤结果等弹窗打开时，导航入口退让。移动端仍由一个入口按需弹出菜单，而不是重建整宽固定底栏。
- 业务内的具体动作（“去工坊安排青枝”、“拜访房间”、“查看缺料委托”）继续保留。它们不是另一套七路由导航。
- 保留浏览器前进/后退、Next 静态导出与 GitHub Pages `/monster-apartment` basePath，不改工坊或公寓的存档键。

## 验收

1. 大厅始终只有一个七按钮 Dock，顺序、标签、尺寸与设计图保持一致。
2. 其他六个路由及同路由的召唤页面均无全宽底栏；左下角小型导航入口位置和样式相同。
3. 展开后有且只有七条正式路由，准确标明当前页面，直接横向跨功能跳转成功。
4. 手机 320×700、390×844、PC 1440×900、1672×941：无页面级横向滚动，入口不遮挡游戏主操作。
5. 原画鉴赏/私人房间等弹窗会遮住场景导航，不会产生悬浮按钮穿透模态窗的问题。
6. 在 A05 移除底栏的空间交给人物卡和右侧资料，不以空白填充；玩法与存档不修改。
7. `Quality` + GitHub Pages 通过后才可宣称已发布；关键场景使用真实浏览器截图和路线点击审查。

## 历史背景

V3.21 原方案把全屏七按钮 Dock 用于全部页面，以消除早期的多个重复底部菜单；但随后 A05、召唤和工坊分别覆盖 Dock 的高度、位置，造成版式漂移。本次改为“一个唯一目的地注册表、两种有明确归属的展现”：大厅完整、子场景小型按需。这保留了数据与路由单一真值，也消除了导致用户反馈的重复固定底栏。

工坊深链接 `?worker=...` 仍由 Pixi runtime 在挂载时自动选中，React 不可重复派发，否则会把工匠反选。这项已有修复不受导航变更影响。
