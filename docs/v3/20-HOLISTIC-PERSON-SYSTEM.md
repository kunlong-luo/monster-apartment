# V3.4 完整人物模拟系统：能力、人格、身心、关系与人生

> **状态：设计规范 / 尚未实施。** 这里的「人物」包括成年的人类 NPC、有灵智的魔物和公寓住客；**并非所有人物都必须套用人类生理量表**。本文件是 V3.4 人物建模的总基线，覆盖旧 [17 六维设计](17-CHARACTER-ATTRIBUTES-AND-POTENTIAL.md) 中「人物只有六项属性」的狭窄解释。六项原始能力继续保留为兼容子集。具体角色样例见 [21 人物完整档案](21-CHARACTER-LIVING-PROFILES.md)。

## 一、设计哲学：不是 20 条能力进度条，而是一个有生活的人

人物由 **身份（是谁）+ 能力（能做什么）+ 性格（如何选择）+ 状态（当下感受）+ 关系（在意谁）+ 经历（为什么成为现在这样）** 共同构成。用户点开一个房间，应能看到性格、习惯、对话、工作方式和真实成长，而不是打开一个 Excel 面板。

**两条硬规则：**
1. **不同数据不能混为一谈。** 身体素质与经验可训练，体力和心情随环境变化，胆小/乐观是稳定倾向，承诺/爱情/信任来自经历，过去不会被一枚戒指重置。
2. **不能无玩法就加数值。** 每个进入正式 UI 的能力都应在已开发系统里有明确用途；未来属性可存在数据定义，但应标记「未启用」，不能假装装备已经提升现实经营结果。

## 二、人物的七大层级

| 层 | 中文 | 代表信息 | 是否数值 | 主要驱动 |
|---|---|---|---|---|
| A | 身份与外形 | 姓名、种族、年龄或生命阶段、外形、职业、衣着、房间与社会身份 | 标签、文本、绘景 | 固定设定与剧情更迭 |
| B | 基础能力 | 身体、认知、精神、社交、生活技能等 **20 项可培养指标** | 数值、有上限 | 等级、训练、工作经验、装备 |
| C | 人格与气质 | 内向/外向、谨慎/冒险、温柔/直率、秩序/自由、勇敢/敏感 | 稳定维度 + 人物特质标签 | 剧情成长，装备不应直接改写 |
| D | 动态身心 | 精力、疲劳、心情、压力、安全感、休息需求、孤独感等 | 短期状态 | 工作、睡眠、房间、互动、事件 |
| E | 社交关系 | 信任、熟悉、默契、冲突、羁绊、承诺、边界与角色偏好 | 有向关系 + 历史事件 | 真实经历、对话选择、合作 |
| F | 技能专长 | 锻造、园艺、贸易、水汽、机械、档案、烹饪、音乐等 | 职业熟练度 + 证书/蓝图 | 真实工作、学习、支线 |
| G | 个人叙事 | 家庭、理想、秘密、恐惧、习惯、重要回忆、道德准则、人生目标 | 文本、剧情事件、阶段 | 剧情/生活选择，非概率洗词条 |

**性别、年龄、身高、体重、物种形态**是按角色需要展示的身份或外观信息，**不是天生战斗倍率和“好坏评分”**。非人形角色不强制填写人类体重或社交礼仪标准。美貌不设统一的「漂亮值」排行榜；人物魅力通过绘景、语言、气质与社交能力体现。

## 三、B 层：20 项基础能力（完整定义，分五组）

### 1. 身体能力（5）

| key | 属性 | 具体边界 | 典型有意义用途 |
|---|---|---|---|
| `physique` | 体魄 | 环境承载和身体适应，区别于纯力量 | 高温/潮湿岗位适应、持续工作稳定性 |
| `strength` | 力量 | 发力与操作重工具 | 熔炉、搬运、机械修理 |
| `speed` | 速度/敏捷 | 操作响应与移动节奏，不等于力量 | 物流、调岗反应、街区信使 |
| `endurance` | 耐力 | 在给定强度下保持行动的能力 | 正常轮班持续度；避免与体魄双倍叠加 |
| `vitality` | 血气/活力 | 恢复能力与生命活性，魔物可理解为灵性活力 | 休息恢复、疲劳后的状态改善 |

**区分原则**：体魄决定「能适应什么工作环境」，耐力决定「能坚持多久」，血气决定「恢复多快」。不能给三者同样的产量乘数。

### 2. 认知能力（5）

| key | 属性 | 边界 | 玩法 |
|---|---|---|---|
| `wisdom` | 智慧 | 经验判断与逻辑分析 | 工艺研究、订单判断、可选调查 |
| `perception` | 感知 | 注意到环境线索、变化和异常 | 温室颜色/水脉、物件调查提示 |
| `memory` | 记忆 | 记住学过的技巧和过往细节 | 研究效率/人物回忆线索，但不跳过主线 |
| `creativity` | 创造力 | 将不同领域的知识重组 | 新配方研发、房间装饰创意 |
| `focus` | 专注 | 在一项任务中保持注意、减少误差 | 精密锻造、研究稳定性 |

### 3. 心灵与意志（4）

| key | 属性 | 边界 | 玩法 |
|---|---|---|---|
| `spirit` | 精神/灵能 | 魔法感应和灵能操控，**不是“开心程度”** | 月心光调谐、孢子/水汽灵能工序 |
| `willpower` | 意志 | 面对困难仍愿坚持个人目标 | 人物成长支线、长期计划倾向 |
| `resilience` | 抗压/韧性 | 面对突发事件恢复平衡的能力 | 黑雾后压力恢复与对话倾向 |
| `discipline` | 自律 | 执行自定计划的稳定性 | 自动学习/排班遵守、作息节奏 |

### 4. 社交与协作（4）

| key | 属性 | 边界 | 玩法 |
|---|---|---|---|
| `empathy` | 共情 | 理解他人的体验，不等于永远赞同 | 居民关怀、人物意见冲突的额外对白 |
| `communication` | 表达 | 把意图说清楚、组织信息 | 合作任务、贸易信息解释、可选谈判 |
| `affinity` | 亲和 | 建立轻松初识关系的能力 | 居民相处、日常交流氛围 |
| `leadership` | 领导/协调 | 帮助他人分工、承担合作责任 | 群体公共工程、轮班协作 |

**注意**：玩家的重要剧情选择**不由数字自动替玩家作出**，亲和或共情也不能强制所有 NPC 爱上自己。

### 5. 生活与手工（2）

| key | 属性 | 边界 | 玩法 |
|---|---|---|---|
| `dexterity` | 手巧/精细操作 | 小型物件与精密动作能力 | 戒指镌刻、照料幼苗、机械微调 |
| `aesthetics` | 审美/艺术感 | 设计、布置、理解艺术的能力 | 房间装修、花艺、可选收藏互动 |

上述 5+5+4+4+2 = **20 项能力**。它们是**内容配置全集**，而不是承诺首个版本立刻让 20 条属性全部拥有百分比加成。首版仅实现与现有工坊/生活场景有关的 6–8 项，其余先用于人物身份和后续剧情条件，并如实显示状态。

## 四、C 层：人格结构不应该直接当战力

**建议用 5 组双向气质 + 人物标签：**
- `reserved ↔ outgoing`：独处/社交倾向。
- `cautious ↔ adventurous`：做决策时优先安全还是探索。
- `structured ↔ spontaneous`：偏好规划还是即兴。
- `gentle ↔ direct`：沟通时柔和还是直率。
- `idealistic ↔ pragmatic`：理想/现实导向（不是道德高低）。

每组用 **-2..+2** 表达偏好，不应把任何端点认定为「弱」或「坏」。例如月纱可外向、谨慎、注重秩序又现实；青枝可安静、谨慎、有原则且理想主义；炽角外向、冒险、直率而务实。

**个性标签（非数值）**：爱开玩笑、爱面子、讲义气、喜欢收藏、害怕被抛弃、讨厌撒谎、习惯晚睡、整理癖、热衷美食、害羞、细心、浪漫、严肃、好奇等。一个角色可以有 3–5 个相互矛盾但真实的标签，并由剧情解释。

**价值观与底线**：承诺/公共安全/自由/成长/生态/交易诚实等用 `beliefs` 和 `nonNegotiables` 文本/标识表达，故事重大节点可变但需要情节理由；不提供「+8 善良」项链。

## 五、D 层：动态身心状态（会变化，但不是疾病模拟）

| 动态值 | 正常变化 | 玩家的可理解反馈 | 设计保护 |
|---|---|---|---|
| 精力 energy | 工作消耗、休息恢复 | 角色坐下、伸懒腰、工作效率提醒 | 自动休息、不强制熬夜 |
| 疲劳 fatigue | 工作和训练累积 | 台词变短、需要休息 | 不随真实离线无限恶化 |
| 心情 mood | 事件、房间舒适度、人物关系 | 表情、房间灯光、短对话 | 不直接判断角色“好坏” |
| 压力 stress | 危机和超负荷 | 犹豫、沉默或主动求助 | 可恢复，不制造无休止惩罚 |
| 安全感 safety | 居民保护、街灯修复 | 夜间愿意走出房门 | 公共工程影响可见 |
| 社交需求 socialNeed | 交流、独处与舒适边界 | 邀请聊天或表示需要安静 | 允许人物拒绝，不扣玩家惩罚 |
| 灵感 inspiration | 环境、观察和爱好活动 | 提供新的蓝图设想或对话 | 不能无限免费抽取资源 |

**不要设计疾病、精神障碍或人格健康的歧视性数值表**。对特殊身体形态与生活需求使用尊重、具体的文本设定，不能依照人类统一标准惩罚魔物。精力/心情不应变成强迫日登录的工具。

## 六、E 层：关系是一张有方向的网，而非单根爱心条

`Relationship(a,b)` 包含：
- `familiarity` 熟悉度（知道彼此多少）
- `trust` 信任（能否依赖）
- `rapport` 默契（合作起来是否自然）
- `conflict` 当前矛盾/未解决议题
- `boundaries` 互动界限（尊重隐私、工作与休息）
- `memories` 双方共同经历过的事件 ID
- `relationshipType` 同事、邻居、朋友、导师、亲密关系（须由剧情双向确认，不自动按好感推断）

人与人可能相互尊重却观点不同：青枝和炽角在工艺上争论，仍可在黑雾夜联手维护稳定器。月纱可以拥有很高的贸易表达能力，仍因旧合同而在伊索面前存在信任缺口。**不允许靠穿戴高阶戒指把“已发生的背叛”直接清零。**

## 七、F/G 层：技能与人生档案

技能不等于天赋：`skills` 从实际经历增长，例如 `smithing` 锻造、`horticulture` 园艺、`hydraulics` 水汽、`barter` 商贸、`investigation` 调查、`cooking` 厨艺、`music` 音乐、`crafts` 手工、`research` 研究、`storytelling` 故事表达。**最初只上线真的能被玩法使用的技能**。

人生档案包括 `history` 经历、`aspirations` 理想、`fears` 恐惧、`habits` 习惯、`likes/dislikes` 爱憎、`secrets` 按章节解锁的秘密、`commitments` 承诺、`milestones` 已完成目标。并非所有角色都需要一个显赫身世，普通 N 住客想要「窗边开一朵花」就足以形成动人的故事。

## 八、属性成长和品阶的真实关系

N/R/SR/SSR/UR 品质控制角色**职业重点能力**的长期成长上限/潜力系数，继承旧 V3.3 首测系数 **1.00 / 1.08 / 1.16 / 1.26 / 1.38**。但：
- 每位角色自带**不同的成长偏好/短板**；UR 也不会自动拥有 20 项最高值。
- 角色等级最高值暂建议相同（Lv.40），成长曲线和能力亲和不同，不以稀有度剥夺 N/R 参与的资格。
- 装备、首饰只能提升**能力/技能**或小幅影响状态恢复/环境舒适度；**不能永久改写“善良、信任、价值观、年龄、过去经历、个性标签”**。
- 装备固定加值与品质成长系数分开计算，不能角色品阶×装备品阶指数叠乘。
- 完整经济性影响必须受工坊现有上限保护，防止 20 项属性一起让生产速度爆炸。
- 角色成长期变化应呈现在行动、台词、房间摆设和故事里，不只是条形图。

## 九、具体交互：人物专属房间怎样看出“她是一个人”

以月纱的会客室为例：
- 刚认识时：外向、谨慎、擅长表达，但低信任、对旧合同话题回避。
- 玩家可以询问她的工作、观察她珍藏的茶杯、查看已公开的合同、提议共同帮助东街。
- 月纱谈贸易时自信果断；提起诺因时停顿；面对伊索批评会先辩解再反思。
- 当玩家完成第三章，桌上新增公开账本，`trust` 随实际事件改善，**她的过去不会消失**。
- 若玩家送她一枚智慧戒环：精密合同解析可能更快，但她**不会因为装备变聪明就突然喜欢或原谅玩家**。

泉泡房间：他热情但担心让人失望，疲劳时会去休息区，学会主动请其他角色修管路。  
炽角房间：豪爽、急躁、热爱精密工具；在第四章之后会更重视安全，锻锤架出现新制作的稳定器。  
青枝房间：安静、耐心，面对被毁坏的花朵会伤心，但当生态系统恢复时能露出真实的喜悦。  
**角色人格、房间和剧情始终共用稳定的 `characterId`**，不能每页写出矛盾性格。

## 十、人物模拟对游戏系统的因果约束

- **自动生产**：能力/技能决定小幅有上限的职业修正，动态精力/排班决定是否休息；情感价值观不替代经营资源。
- **对话选择**：人格影响说话方式与可选反应，关系/历史影响信任，玩家决定重要路线；不采用「智慧 50 自动跳过全部对白」。
- **房间生活**：喜好、习惯、社交需求驱动角色动作/陈设变化；房间中的秘密与剧情章节同步，不能提前剧透。
- **装备/锻造**：装备对能力提供固定属性，特殊饰品有职业用途；不通过首饰永久修改性格标签。
- **抽卡**：稀有度只影响潜力和演出，普通住客也有完整人格、职业能力和小故事。
- **CG 收藏**：真正完成角色人生事件才解锁相应回忆，不按总属性达到某个数字机械发放。

## 十一、技术模型（建议接口；非已提交源码）

```ts
type AbilityKey =
  | 'physique' | 'strength' | 'speed' | 'endurance' | 'vitality'
  | 'wisdom' | 'perception' | 'memory' | 'creativity' | 'focus'
  | 'spirit' | 'willpower' | 'resilience' | 'discipline'
  | 'empathy' | 'communication' | 'affinity' | 'leadership'
  | 'dexterity' | 'aesthetics';
type AbilityScores = Record<AbilityKey, number>;
type TraitKey = string;
type CharacterIdentity = {
  characterId: string;
  name: string;
  species: string;
  lifeStage: 'adult' | 'other';
  ageYears?: number;
  genderIdentity?: string;
  appearance: string[];
  profession: string[];
  favoriteThings: string[];
  habits: string[];
  motivations: string[];
  fears: string[];
  coreValues: string[];
  personalBoundaries: string[];
};
type Personality = {
  traits: TraitKey[];
  reservedOutgoing: -2|-1|0|1|2;
  cautiousAdventurous: -2|-1|0|1|2;
  structuredSpontaneous: -2|-1|0|1|2;
  gentleDirect: -2|-1|0|1|2;
  idealisticPragmatic: -2|-1|0|1|2;
};
type LivingState = {
  energy: number; fatigue: number; mood: number; stress: number;
  safety: number; socialNeed: number; inspiration: number;
};
type CharacterLifeProfile = {
  schemaVersion: 1;
  characterId: string;
  identity: CharacterIdentity;
  intrinsicRarity: 'N'|'R'|'SR'|'SSR'|'UR'|null;
  abilities: AbilityScores;
  abilityAffinity: Partial<Record<AbilityKey,number>>;
  personality: Personality;
  livingState: LivingState;
  skills: Record<string,number>;
  biographyFlags: string[];
  personalQuestIds: string[];
  roomId: string;
};
```

**安全迁移**：保留旧 `cozy:v1` / `workshop-v2-lab`，新档用 `characterId` 关联既有住客/剧情人物；老六项键 `physique/wisdom/strength/spirit/vitality/speed` 原样映射，不删除，新增十四项用**每人独立配置表**初始化，不能无声给所有人一份相同人格或覆盖历史档案。

**显示策略**：人物图鉴默认只露出该人物最相关的 4–6 个能力、当前心情/精力及一句性格描述；「完整档案」再分层查看 20 项、关系、兴趣、人生回忆、装备详情。避免一次在手机画 20 根进度条。

## 十二、P0/P1/P2 工作范围与验收

- **P0 保持原优先级**：工坊真正自动生产和存档稳定先完成，本需求不阻碍。
- **P1 人物纵切片**：月纱、泉泡、青枝、炽角各展示身份、3–5 个标签、6–8 项有业务效果的能力、动态精力/情绪、1 条人物关系和 1 个房间变化；普通对白与正式剧情可以看出个性差异。
- **P2**：扩到 20 个可配置能力和完整生活数据；新增可培养技能和各人物房间行为；装备/训练显示来源可解释且有上限。
- **P3**：更多关系事件、喜好、爱好、细腻情绪演出、故事/衣着/生活习惯变化；用玩家测试观察人物是否真正被记住。

**必须测试：** 相同角色在图鉴/工坊/房间的六维和其它能力一致；换戒指不改人格/关系；疲劳恢复与工作时间有明确界限；低品阶不会丧失全部价值；NPC 重大选项不可由单项数值替代；不开新 UI、断网、重新进入和离线恢复不会生成不同的人生档案或重复奖励。
