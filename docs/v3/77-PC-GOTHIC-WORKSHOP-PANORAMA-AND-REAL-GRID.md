# V3.77 · PC 哥特工坊场景化重制 / 真正 15 格棋盘双视图

**2026-11-07，主分支直接实施。** 承接 V3.76 已接入的三类设备、九张透明 CG 审核候选及白边派生清理。

## 设计目的

按此前认可的哥特式 2D 游戏参考推进，不再把 PC 工坊的主舞台塞成 5×3 的小方格或一排常驻大按钮。PC 主舞台表现为哥特大厅中的三台大型设备：水汽泵、孢子温室、晶核熔炉。月纱的视觉展示、委托和产线信息转为边缘小面板，机器占据中间的大区域；按钮缩小并按需出现。手机和短屏继续使用已测试过的精密 15 格舞台。

## 本轮真实代码实现

- `src/components/moonwork/workshop-cinematic-stage.tsx`：纯展示、无独立生产状态的三工位场景，直接从 **当前 WorkshopState** 读取设备位置、最高等级、工匠、生产运行/缺料/待派状态和真实仓储。无独立派工器、隐藏玩家库存或额外存档。
- `src/components/moonwork/workshop-cinematic.css`：完整场景 CG 覆盖中间可用舞台，三台独立机体大比例展示，具有受控黄铜/紫黑/玻璃灯光、上下景深与小状态牌。月纱及委托模块停靠在左右边缘，设备始终是主体。仅当视口至少 1100×730 时启用。不开启廉价的 SVG 火花；尊重 reduced motion。
- `src/components/moonwork/workshop-stage-container.tsx`：桌面默认「生产全景」；可直接切换「精密建造」查看真实 15 格 Pixi 舞台。需要建造、搬动、派工时自动呈现精确地块，操作完成后恢复全景。旧舞台的 WebGL Canvas、逻辑节拍、资源流向、工匠和碰撞区域没有被销毁或移动。
- `v2/src/workshop-runtime-contract.ts` 和 `v2/src/main.ts`：新增类型安全 `select-plot` 操作，从全景点击机器调用原有 `plot(index)` 函数，进行真实地块选中与移动/升级/拆除准备；未建造机器仅进入选择建设和精密棋盘，不通过全景直接扣钱。
- `src/components/moonwork/workshop-client.tsx`：场景与棋盘选择仅存在 React 内存状态，不进入存档、不增加新游戏路由；工程模式与 UI 切换不是两套生产系统。
- 普通玩家继续使用已部署的旧 AVIF 备用机体素材；审核链接 `?machine-art=review` 从已成功导入 GitHub 的九张 CG WebP 获取级别匹配的新机体。**不会自动把审核中的资产升成正式 ready**。新版 CG 仍有边缘与画质细节需要持续美术打磨。

## 必须保持的不变量

1. **只允许原始 15 格的 engine 和 autosimulation 写游戏存档**。全景与格子点击均调用同一个现有动作协议，不重算产量、成本、等级、奖励与概率。
2. 建设/移动/派工等需要坐标的操作必须在可触达的网格模式中完成；不提供看似可点击却无效果的空按钮。
3. 紧凑 390px 手机和未满 1100px 或高小于 730px 的视口不出现全景大图和额外遮挡层。
4. 无审核授权的 CG 与工作动画仍不进入生产资产索引；概念素材与正式游戏人物 CG 分别验收。
5. 场景按钮可以键盘访问，设备区域有语义标签，画面模式具有 `aria-pressed` 状态；日常动作无延长动画或强制进场过场。
6. 视觉回归要覆盖默认桌面全景、工位选中、在全景选择尚未建设的熔炉自动进入棋盘、精密棋盘返回全景、手机旧棋盘、正常生产以及储存内容不变。

## 仍待打磨

与以前参考效果图之间仍有差距：目前展示的普通版机器是旧版占位图，CG 审核只在显式预览模式；人物工匠现阶段以真实头像说明状态，尚未制作匹配全景比例的完整透明工作立绘，三台机体也尚无与新 CG 对齐的四帧工作动画。下一阶段美术重点应是大型独立设备最终原画、工匠工作姿态和全景层次/灯光整合，**不是重复创建更多后台审核工具**。
