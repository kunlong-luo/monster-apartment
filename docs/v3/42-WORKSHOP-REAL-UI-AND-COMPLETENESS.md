# V3.20 · 七页面核查与工坊派工可用性

## 被掩盖的具体问题

旧 Quality 只验证七个页面可以打开、静态导出和部分主线操作，不能证明全部玩法完成。工坊旧 CSS 将 `.options` 统一设成横向 flex，覆盖 React 的网格和纵向列表；底部控制台只有 198px 高却同时放三组工匠、三个设备、日志和按钮，导致重叠、挤压、溢出与缺少可读操作空间。

此外，原“自动分配”只执行 choose-worker，未把任何工匠派到设备，却显示“已匹配”；日志中出现固定虚构时间和设备“已建”即“生产中”状态。新版本把该操作明确命名为“选择空闲工匠”，告诉玩家继续点击 Pixi 设备完成派工；日志时间标记改为“本班次”，设备标签改为“已建造／未建造”。

## 本轮改动

- 桌面：三个实际功能区均有足够高度与独立滚动区，工匠为真正纵向的三行，文本和操作不重叠。
- 手机/窄屏：采用“设备／派工／生产”标签，一次展示一组完整内容；不再把三组挤进两列和 180px 的容器。
- 加入 1440px / 390px / 320px 浏览器布局回归：三个工匠可见、列表不是横排、矩形不重叠、场景和控制均可用。
- 构建：仓库只有 `bun.lock`，旧工作流却使用 `pnpm install --frozen-lockfile`，导致 CI 全部失败。CI 现使用 Bun 的锁定安装，保留 pnpm run 命令。

## 七个页面真实覆盖范围（按代码核查，不代替人工体验）

| 页面 | 已实现主要可交互流程 | 仍不应视为完工 |
| --- | --- | --- |
| 大厅 | 游戏导航、月纱对话入口、资源和当前主线显示 | 对话分支短、人物动态素材未生产完成 |
| 公寓 | 建房、入住、装修、搬家、经营计时和安全存档 | 独立场景美术及角色互动仍在概念到正式资源过渡 |
| 工坊 | Pixi 建设、派工、设备布局升级、产出班次、委托预测 | 派工仍需选人物后点设备；自动排班算法没有实现，不标称已实现 |
| 月光街 | 居民交易、材料市集、访问区域入口 | 店铺以交易面板为主，未建立完整独立店内玩法 |
| 委托大厅 | 实际晶核订单、高额订单风险、月纱特别委托 | 丰富的多阶段故事委托未全制作 |
| 角色图鉴 | 工匠展示、岗位状态、拜访角色私室、线索及记忆 | 收藏级人物动态立绘和完整成长装备尚未完成 |
| 仓库 | 晶核、水汽、孢子存量、有效期内采购 | 自定义整理、装备仓储与打造链路尚未实现 |

通过路由测试 ≠ 页面已完成。下一批测试必须以功能状态变化及 UI 可视质量为验收依据。
