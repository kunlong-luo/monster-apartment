# V3.2 角色专属房间与可进入式对话系统 PRD

> **状态：Proposal，尚未实装。** 用户确认的核心要求：**每位人物有独立房间；玩家可以走进房间、看到人物、与其交谈；每个人物的房间都应有一张精美专属展示画面。** 本规范是 [12 角色招募](12-GACHA-RECRUITMENT-PRD.md)、[13 人物卡池](13-CARD-ROSTER-AND-ART-DIRECTION.md)、[08 对话交互](08-NARRATIVE-DIALOGUE-UX.md) 与 [09 收藏 CG](09-CG-COLLECTION-AND-ART.md) 的实施接口。

## 1. 不可妥协的玩家体验

从人物卡点「拜访房间」→ 哥特式公寓走廊/角色专用门进入 → **专属全屏精美房间绘景**，看到人物按生活习惯自然活动 → 可与人物交谈、观察房间中的 2–4 个有意义的物件、触发关系事件 → 可自由退回走廊/图鉴，不丢经营进度和当前剧情。

**不同人物绝对不能共用同一张房间背景只换头像**。可以共用渲染组件、材质框架、通用灯光/门把素材，但每位人物必须有符合职业与性格的**独立主题、独立构图和至少一张专属房间母版**。即使 N 普通住客也值得精致展示；UR 主要在特殊演出与独特秘密中体现稀有，而不是只有红框。

- 首次召唤到可招募住客 → 自动在「角色楼层」生成其**永久可拜访的个人空间**，不另收建设费，不因当前房间数已满而不能进入。
- 首次在主线正式认识 NPC → 解锁对应「人物房间 / 私人工作室」的拜访入口；开门条件可按剧情阶段/人物许可控制，**不要求抽到主线 NPC**。
- 同一人物无论抽到多少次，只生成一个房间；重复卡只处理碎片，不会生出复数居民。
- 角色不在线/外出/工作时，房间仍可以作为已获许可的空间查看其陈设、回忆或留言（可展示「外出中」），不得因为角色短暂不在就把房间关死。
- 房间展示、背景音效、角色动作的成功或失败**不能**改变库存/星币/概率保底/订单结算。

## 2. 和现有六间公寓业务房间的兼容约定

当前 `src/core/cozy-engine.ts` 的 `CozyState.rooms` 是有限的实体经营房间，存储 `type/resident/decor`，参与现有收益及入住规则。它们**继续保留为经营房间/住宅分配数据**，不要为了「一人一个可查看的房间」直接改成无限个自动产币房间，造成旧档损坏和收益爆炸。

V3.2 将两种概念明确分开：

| 概念 | 含义 | 对经济的影响 | 唯一标识 |
|---|---|---|---|
| `ApartmentRoom` 经营房 | 已有可建造、安排住客、产生收益的实体房间 | 保持旧 `cozy:v1` 规则及成本 | `roomSlotIndex` |
| `CharacterSuite` 人物私室 | **一人物一独立可拜访场景**，包含专属美术、对话、场景物件、秘密进度 | 默认没有独立租金/自动产出，仅真实事件触发小型技能/剧情 | `characterId` 唯一 |
| `StoryCG` 回忆插画 | 人物或剧情达到条件后解锁的大图 | 纯收藏，不是房间本身 | `collectibleId` |

**一位拥有的住客即使尚未安排进六间经营房，也拥有一间可进入的专属空间。** 在剧情逻辑上可理解为公寓逐渐开放的「梦境侧翼 / 角色楼层」；不计入经营房间容量，不会给免费房租。将来扩建真实楼层可以改变走廊外观，但不能把「进入自己已收藏角色的房间」作为付费/随机门槛。

**固定剧情 NPC** 的专属空间可以是公寓临时客室或其在月光街的工作兼私室（例如月纱商会会客套间、阿洛钟楼书房），通过人物卡/剧情中「拜访他的房间」到同一个 `CharacterSuite` 视图，**不宣称他们都实际长期住在公寓**。

**迁移与隐私**：已有 `known/rooms` 住客不得丢失；第一次升级仅从已拥有的 `characterId` 幂等派生默认私室；旧房间装饰和收益不被重写。故事 NPC 初见标志来自世界状态；剧情许可有解释，不能把房间设计为未经允许闯入的偷窥玩法。

## 3. 从七个正式页面进入房间

- `/apartment/`：从哥特走廊找到住客房门/门牌 → 点击门进入私室，返回公寓保留镜头与滚动位置。
- `/characters/`：卡片详情显示「拜访房间」 → 同一私室场景；未招募角色不显示其房间全貌与隐藏道具。
- `/`：主线提示可跳到某人物已开放的私室。
- `/town/`：遇见已认识的人物，可显示「拜访住处/工作室」。
- 工坊等其他界面不新增大面积强制房间按钮；剧情需要时只出现紧凑的相关人物入口。

**七个正式路由不变**，优先使用公寓/图鉴的场景内面板或内部状态切换，不新增八个 URL 入口。可支持按 `characterId` 深链恢复，但不泄露未解锁绘景/CG；返回要自然过渡而非全屏重新请求失真图。

## 4. 单个私室的标准屏幕结构

1. **绘景层**（占视觉中心）：独立 16:9 或适应宽屏的 2D 室内 CG，家具体现人物身份；禁止把 UI 烧录进绘景。
2. **人物层**：优先独立透明立绘/角色精灵，在适当室内位置坐着、整理、阅读、工作或休息；用 2–4 个清晰状态而非无条件上下漂浮。
3. **氛围层**：只有适合场景的光线、天气、窗帘、炉火、植物、钟声；真实表现角色动作与剧情变化。
4. **热点层**：每个房间 2–4 个可解释的物品，例如日记、工具箱、信件、盆栽；不设遍地无意义点击点。
5. **交互层**：左下/右下的小型「交谈」「观察」「赠予已解锁物品/共同活动（后续）」「离开」。未解锁功能不堆按钮。
6. **对话层**：底部字幕安全区显示真实人物表情和对白，选项通常 2–3 个，带历史回看与跳过已看。
7. **导航层**：小门牌/人物名字、返回走廊按钮、可关闭背景音效和降低动画。移动端原画安全裁剪，人物脸部不被字幕遮挡。

**一个房间会随着关系与章节产生变化**：初见、熟悉、信任、人物支线完成、主线结局后。首版建议复用同一高质量房间母版，用可单独替换的道具层/光效/人物动作实现变化；**不是为每个关系阶段强制生成一整张完全不同的背景**。

## 5. 对话与拜访的实际玩法

**四类对白，不能全是重复招呼：**

| 类别 | 触发 | 结果 |
|---|---|---|
| 日常语音/短对白 | 首次拜访、角色状态变化或冷却后的正常访问 | 角色更鲜活，短句可跳过，不靠次数涨好感 |
| 观察物品 | 玩家首次检查具有线索的 2–4 件布置 | 发现人物小习惯、图鉴注释、可选线索；事件一次性 |
| 个性决策 | 支线满足真实条件后人物主动提出问题 | 2–3 个有后果的选项，影响关系/经营政策/后续台词 |
| 回忆与隐藏互动 | 章节/人物支线完成、彩蛋线索满足 | 解锁 StoryCG 或隐藏对白，重看无第二份奖励 |

**互动节奏**：每次拜访都能有自然变化，但不保证每次都有新奖励；日常对话可按剧情状态选句，避免同一句固定台词连播 10 次。没有强制「每天摸头 3 次」「连点 10 次才能提升好感」。

**房间与生产**：角色正在工坊上班时可显示「泉泡在水泵旁忙碌」与环境/留言互动；不能为了留在私室里对话而在模拟器中凭空创建第二个同一角色。玩家主动发起剧情对话时可以使用静态对话分身呈现，但领域工作/收益仍由一个真实角色决定。

**角色关系**：首次合适的选择记 `sceneId + choiceId` 幂等事件；日常问候不无上限加关系。人物可能短暂拒绝会面，但仍给可读、可恢复的说明。

## 6. 美术与技术资产规格

每位人物**独一张精美私室场景原画**，加人物透明层、2–4 个可分层互动道具。首批设计表见 [15 人物私室图鉴](15-CHARACTER-ROOM-BIBLE.md)。

| 资产 | 母版建议 | 必须质量 |
|---|---|---|
| `room/<characterId>/master` | 2560×1440 以上、16:9、无 HUD 文本 | 每人独立透视、陈设、光源和故事标志物；构图有角色空间 |
| `room/<characterId>/mobile` | 1440×2560 或为手机重绘安全裁切 | 看清角色面部和 1–2 个关键物件，不拉伸 |
| `room/<characterId>/portrait` | 透明人物高 ≥1024px | 角色外形与卡牌/图鉴一致，不能是伪透明 |
| `room/<characterId>/props` | 分层道具透明图（或局部） | 仅放可真实交互/会变化的物件 |
| `room/<characterId>/thumbnail` | 适合房门/图鉴的独立缩略图 | 低内存快速选择、未解锁不剧透 |
| `room/<characterId>/ambient` | 轻量可选环境演出 | reduced-motion 下可静态、声音可静音 |

制作时严格遵守人物圣经中的年龄、服饰、形象与**伏笔时序**，例如月纱初见房间可以见月纹但不能看懂旧合同秘密。所有 AI 原画候选须逐张审核，不把概念图当交付。

**成本控制**：优先实作 3 间现有住客私室 + 1 间剧情角色私室（泉泡、芽核、露珠灵、月纱）；验证在 390px 手机与 1920px PC 上效果后扩到 12+8 人。未审核的独立房间可在门牌显示「房间整修中」并用统一占位，但**不能对外宣称每个人物专属高清私室均已完成**。

## 7. 可实现数据契约（建议，非现有源码）

```ts
type CharacterRoomId = string; // = stable characterId, not roomSlotIndex
type RoomPose = 'idle'|'work'|'reading'|'resting'|'talking'|'away';
type RoomEventKind = 'inspect'|'dialogue-choice'|'scene-completed'|'secret-discovered';
interface CharacterSuiteDef {
  characterId:string;
  roomThemeId:string;
  assetManifestKey:string;
  firstAccess:{kind:'recruited'|'story-met'|'story-permission';eventId?:string};
  hotspots:Array<{id:string;sceneId?:string;visibleAfter?:string;spoilerLevel:number}>;
  dialogueSceneIds:string[];
  poseIds:RoomPose[];
}
interface CharacterSuiteProgress {
  schemaVersion:1;
  characterId:string;
  visited:boolean;
  inspectedHotspotIds:string[];
  viewedSceneIds:string[];
  unlockedDecorIds:string[];
  currentMood?:'calm'|'busy'|'happy'|'concerned';
  lastVisitAt?:number; // UX only; no daily mandatory gift counter
}
```

**单一权威性**：角色的存在与已拥有状态从当前招募/主线事件获取；room view 不创造角色，角色职业运行态来自生产/公寓引擎。首次解锁房间通过稳定 `characterId` 推导，不生成需要重新抽的门票。剧情/CG/隐藏道具的唯一奖励通过世界状态事务确认；重新渲染房间不会产生第二份。可能跨路由切换的一段对白需可恢复，不得强制重看开头。

## 8. UR 神话 · 月蚀房间特殊演出

**用户确定：UR 品阶主题色为红色。** 红是卡牌**稀有度**而非角色善恶或危险警示。详见 [16 品阶视觉 Token](16-RARITY-VISUAL-TOKENS.md)。

- UR 私室入口：绯红月蚀纹章、深红丝绒/暖铜结构，门牌有不同于故障警告的**纹样 + UR 文本标签**。
- UR 人物自己的房间主体仍必须符合其职业与性格；**红色不意味着 12 位角色共享相同红背景**，也不要求每件家具都涂红。
- 访问 UR 私室的第一次揭幕：短暂红月照进窗帘，月蚀光环向外散开，角色现身；2–4 秒可立即跳过，之后普通进入不强制重播。
- 在 room image 上不要叠红色超亮滤镜遮住细节；与 SSR 金色、SR 紫色清晰区分。
- 角色在房间里仍有普通时刻、情绪和故事；不是只能站在红色祭坛上的静态奖杯。

## 9. 必须验证的边界

- 每个已经拥有的 `characterId` 最多一个私室；抽到重复不额外生成房间；未拥有不可偷窥其 CG。
- 旧存档经营房数量与租金不变；新私室不给经营收入、不消耗新房间槽位；首次迁移生成已拥有住客的私室访问权限。
- 被派工角色没有两个真实实体；工坊运行/离线结算和房间对话可同时正常且资源不重复。
- 某人暂不在房、剧情访问被婉拒、人物忙碌，都有符合人格的文字，不会空白死锁。
- 所有房间都能进/退/刷新；低端机只加载当前房间，不一次性渲染 20 张 2K 图片。
- 320/390px 手机安全裁切，页面返回按钮不遮角色头像，室内热点大小 ≥44px，键盘与关闭动效可操作。
- 画面必须为每人独立高质量母版、同人同形，资源加载失败可读/可退，但不把占位视作完成。
- 访问中的剧情选择、秘密发现、CG 解锁跨页/多标签幂等；重看/跳过不重复加好感、送券或给钱。

## 10. 交付优先级

**P1 试验**：泉泡、芽核、露珠灵、月纱四间私室的视觉/交谈模型；玩家从图鉴/公寓进入并成功返回；每人 1 句初识、2 个物件/线索、1 个短选择、1 个可追踪关系事件。  
**P2 首批正式**：12 位可招募住客完整独立室内图，8 位主线 NPC 各有可拜访的个人空间；稳定的对话、剧情解锁、CG 展示和所有旧档兼容。  
**P3 精修**：各角色房间分层动态、心情/故事引发的场景变化、环境音效、更多室内彩蛋和个人结局回顾。

**先实现可进入、可交谈、可收藏的四间房，确认好玩后再把每人房间美术全量投入制作。**

## 11. V3.3 私室的衣柜、装备盒与生活对白

每个人物私室可选择 1 个轻量「衣柜/首饰盒/工具架」互动，显示**真实穿戴中的首饰/器具**和相关六维变化；选择其他已锻造物品需要确认，不能靠重复查看收取角色装备或增加好感。

- 一人一间私室保持纯角色/剧情展示：装备和锻造不增加私室房租，也不创建第二位生产工匠。
- 能够根据角色体形显示合理佩戴方式：泉泡佩戴浮空水纹环，炽角拿锻锤、青枝佩戴苔光饰件，N 小精灵不强套人形护甲。
- 「锻造完成」「首次佩戴某专属器具」可以成为房间一次性新增对白，反复看不重复增加经验/材料/CG。
- 房间 UI 里有「查看穿戴」「打开装备仓」「继续交谈」的清楚入口，主画面始终可见，不卡在复杂后台表格。

详见 [17 六维属性](17-CHARACTER-ATTRIBUTES-AND-POTENTIAL.md) 与 [18 装备锻造](18-EQUIPMENT-FORGING-PRD.md)。
