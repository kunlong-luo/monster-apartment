# V3.1 开发路线图、任务拆解和验收清单

> **规划状态，不是已完成工作清单。** 必须先跑通稳定的自动生产，再铺开剧情和美术。README 的现有游戏入口及 V2 功能仍为当前发布事实。

## 1. 发布原则

- 唯一正式技术体系：Next.js App Router + React 19 + TypeScript + Tailwind CSS 4 + Motion + PixiJS 8；Zustand + Dexie 本地优先。**不恢复旧 Phaser UI**。
- 保留七个正式路由、旧 V2 工坊键和旧 cozy 公寓键；新世界进度使用独立版本化存档。
- 生产系统只有**一个权威模拟器和唯一结算事务**；不能将“设备开机动画”和“真实产量计算”放在不同算法中。
- 每阶段独立可玩、可测试、可回滚；正式功能进度与文档状态分开标记（Planned / In development / Verified / Released）。
- 原画不等同动画帧；临时 Canvas 精灵只是兼容回退，未审核原画不能冒充商业游戏正式美术。

## 2. P0：自动生产可玩闭环（必须先完成）

| ID | 工作包 | 涉及模块 | Definition of Done |
|---|---|---|---|
| P0-01 | 设计设备周期、容量和输入预扣事务 | `v2/src/workshop-production.ts` 等纯规则模块 | 同一时间轴严格守恒；两台设备不能消费同一份材料 |
| P0-02 | 实现 `simulateUntil(now)` 与事件 ID | 规则模块 + 存储适配 | 重复调用同一 now 幂等；时间顺序稳定 |
| P0-03 | 全站持续生产的统一调度与订阅 | `src/lib/moonwork/`、工坊侧载桥接 | 切七页仍生产，UI 无不同步 |
| P0-04 | Dexie V3 存档、旧档安全迁移、失败回退 | IndexedDB + 迁移器 | V2 数据不丢；坏档不静默覆盖 |
| P0-05 | 仓储容量、订单自动交付和公共预留 | 订单/仓库/纯业务规则 | 只扣一次；预留不重复出货；风险可见 |
| P0-06 | 设备状态及工匠行为与真实业务关联 | PixiJS stage、精灵 | 启动/缺料/运行/仓满/出货均有可辨反馈 |
| P0-07 | 多标签协调与离线补算上限 | 事务、Web Locks 兼容 | 两标签不重复结算；离线 ≤8h 可恢复 |
| P0-08 | 保留旧手动班次的回滚/迁移路径 | feature flag、存档门禁 | 全部 E2E 通过后再默认自动生产 |

### P0 必须优先冻结的未决产品参数

- 基础设备周期暂定 30/45/60 秒，输出 2/2/2；专业技能/升级如何影响实际周期或产量。
- 每台设备的储罐容量、仓储最大容量；满仓时禁止启动还是暂停在制品。
- 订单真实营业时间、是否自动续约、离线不罚款时如何解释限时委托。
- 多标签原子性/版本冲突策略及 IndexedDB 不可用时单标签保守回退。
- 游戏和现实时间的关系（剧情章节是事件进度，不随每个生产周期推进日历）。

这些项目未冻结前，不得在剧情文本里承诺具体发货用时/罚款数额。

## 3. P1：20 分钟序章 + 第一章纵切片

## 4. P2：完整主线与人物支线

- 第二章：月纱的交易、公共照明与贸易路线选择。
- 第三章：公寓住客反应、钟楼账本、月纱旧合同。
- 第四章：黑雾状态、应急配方、临时稳定器与公共供能恢复。
- 第五章：诺因对话、三份新材料与月心灯最终修复。
- 终章：生态 / 繁荣 / 永续三结局，以及保留存档的自由经营。
- 八位重要 NPC 各有三个阶段的支线，优先泉泡、青枝、炽角、月纱。
- 新建筑/配方只有在真实经营与故事有作用时加入；不为了收集按钮增加 30 台功能重复机器。

**P2 验收：** 不抽 UR、不联网、不付费也能从新档走完主线；拒绝月纱合同或一次订单失败后仍有可恢复路径。

## 5. P3：美术、音频、稳定性与发布

- 三位工匠各至少：idle 8 帧、walk 8 帧、work 8–12 帧；victory/tired 可在 P3 再扩展；先审核人物身份一致性。
- 设备有 Lv.1–3 独立高清美术，水泡/孢子/火花独立的工作表现，不把背景截图裁成假透明精灵。
- 月纱等成年 NPC 有待机、说话、交易、不同表情的实际可用美术资源。
- 音效：水泵、温室、熔炉、交付、钟声；声音不随快速路由切换重复播放；可静音。
- 文本：可回看、跳过已看，字幕正确、段落不溢出，中文/英文可扩展。
- 目标帧率：桌面 60 FPS（同设备受测）和手机合理稳定性；性能验收用真实设备和工具测量，不作未测承诺。
- 资源包体、加载失败回退、跨标签页、断网回到页面、旧档数据恢复、操作/导航动画平滑、图片不失真全面验证。

## 6. 测试验收矩阵

| 测试类别 | 必测范围 | 自动化方式 |
|---|---|---|
| 规则单测 | 时钟序、原料守恒、专业加成、产量、满仓、订单预留 | Vitest 纯函数 |
| 数据迁移 | V2 初始/首单/第五单/委托/异常档、公寓老档 | fixture + property/regression |
| 幂等 | 多标签并发、断点重试、同事件多次处理 | IndexedDB 事务测试及 Playwright |
| 离线 | 1min、8h、超过 8h、倒退时钟、后台挂起 | 注入可控时钟 |
| 页面 | 七页首屏、刷新、返回大厅、深链/历史路由 | Playwright Chromium |
| UI | 手机 320/390、平板 820、桌面 1280/1920 | Playwright + 人工截图复核 |
| 可访问性 | 键盘、触摸、aria、减少动画 | 浏览器回归 |
| 叙事 | 重看/跳过不领奖；三结局前置条件；支线不软锁 | 事件驱动单测 + E2E |
| 生产视觉 | 缺料真的停、产出数字真实、资源动画来源正确 | E2E data hooks + 视频回看 |
| 稳定性 | 20min 前台、反复切页/挂载/卸载、低端机 | 性能记录 + 手测 |

**CI 门禁：** `pnpm install --frozen-lockfile`、`pnpm typecheck`、`pnpm lint`、`pnpm test`、`npm --prefix v2 run typecheck`、`NEXT_STATIC_EXPORT=1 pnpm build`、`pnpm e2e`。全部通过后再检查 GitHub Pages 部署结果；不得只因本地可编译就宣称已上线。

## 7. 本轮与下一轮落地的区别

- 本轮成果：`docs/v3/` 一套完整的产品、规则、人物、剧本与任务验收文件；**没有把自动生产功能标为已实现。**
- 下一轮优先建 P0 的测试和领域模型，在 feature flag 下实现单机自动周期与迁移。
- P0 验证通过后，再逐步接入角色动作和剧情触发；UI 先为主舞台服务，按需使用小面板，不恢复长页面管理后台。
- 任何新增功能须补充至少一项可判断其**可玩性**的验收，而不仅是是否渲染了按钮。

## 8. 风险与缓解措施

| 风险 | 早期信号 | 解决原则 |
|---|---|---|
| 自动生产导致无限产币 | 离线仓库和现金暴涨 | 有界时钟、储存容量、不可重复结算、人工平衡回放 |
| 多标签重复产出 | 切标签后多出晶核 | 原子事务+事件 ID 幂等 |
| 公寓与工坊经济被混淆 | 两页星币余额不一致且无法解释 | 独立货币、统一世界事件，不隐式合并 |
| 线索丢失导致主线断开 | 已完成订单却无法解锁下一幕 | 事件回放修复、可重取线索、独立任务检查器 |
| 剧情覆盖画面 | 工坊被弹窗遮住无法操作 | 轻提示进入剧情、可跳过、移动端不遮主交互 |
| 正式画质仍低劣 | 放大旧低分辨素材 | 审核可寻址透明 WebP/图集，失败可退回但不冒充完成 |
| 功能增长无新乐趣 | 页面新增很多按钮但留存变差 | 严格限制范围，保留实际有选择价值的操作 |

## 9. 推荐开发顺序（最小下一步）

1. 制定 `FactoryClock`、`ProductionCycle`、`InventoryLedger` 类型及纯函数规格。
2. 用可注入虚拟时间写生产/订单/离线/幂等测试。
3. 做本地权威事务与迁移器，在隐藏开关下开始自动生产。
4. 接上 Pixi 设备状态和 React 统一 HUD；删除强制手动「开始一天生产」主按钮。
5. 实现序章/第一章最小剧情状态与街区照明事件。
6. 再投入正式高清透明精灵与第二章后续内容。

**版本冻结记录：** 这份路线图是计划，不包含具体实现工时承诺。任何产品参数改变时，请更新 [02-AUTO-PRODUCTION-PRD.md](02-AUTO-PRODUCTION-PRD.md) 并记录决策。
