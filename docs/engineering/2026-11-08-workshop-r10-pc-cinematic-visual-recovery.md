# R10 · PC 工坊全景的设备视觉回收与交互精修

日期：2026-11-08。范围：桌面端默认 1440×900 及其他满足 `min-width:1100px, min-height:730px` 的生产全景。游戏机制、15 格 Pixi 热区、存档与页面路由不变。

## 实际视觉问题与原因

对照最后一轮 [Desktop Visual Review](https://github.com/kunlong-luo/monster-apartment/actions/runs/42444729014) 中的 `visual-evidence/workshop/desktop-workshop-scene-1440.png` 和 `desktop-workshop-stage-priority-v390.png`：

1. 默认普通游戏的主设备来自低清晰度 legacy AVIF；原 CSS 的水汽泵 1.90 倍、温室 1.60 倍、熔炉 1.70 倍放大将压缩痕迹直接铺到舞台上，明显失去原设计稿的精致度。当前审核候选并未标记 `ready`，不应悄悄切换为正式美术。
2. 整台机器实际是一个按钮，原 CSS 在选中和 hover 时给全设备区渲染大面积边框及背景，视觉上变成三张大型网站卡片而不是庄园里的物件。
3. 设备与地面的空间关系较弱：底部缺少与水汽／植物／熔核一致的材质光影提示。

## 本轮修改

- **只对默认旧素材控制放大**：水汽泵 1.28、温室 1.18、熔炉 1.25，最大图片渲染容器宽度 400px；显式原画审核模式仍然保留较大的 512px 候选预览空间。
- 交互仍是原有全尺寸语义化 `button`，但取消整块卡片式 hover/selected 背景，改为局部地面光斑、细窄的材质选中线与铭牌亮度提升；键盘 `:focus-visible` 的明确虚线轮廓继续保留，不能牺牲无障碍操作。
- 光斑没有额外 DOM、Pixi 图形或运行时事件，复用每个 craft 的色彩变量，避免新增粒子和 WebGL 负担。
- 增加定向 Playwright 视觉证据，检查三个默认设备缩放上限、透明卡片边框、地面光影、选中态提示和上下文操作仍可用，输出未选中和选中两张 1440px 浏览器截图。
- 未审核的机器美术仍明确保留 review 状态；这些 CSS 改善不能替代下一轮真正的 512px 透明设备绘画和等级差异生产。

## 退出条件

以同一 main SHA 的 Quality、Desktop Visual Review（含新桌面截图）及 GitHub Pages 为准。由于仅编辑了生产全景的 CSS 和浏览器测试，不改 V2 WebGL 渲染器、堆快照基准或存档。

## 第二次实际截图核对与落地点校正
- 第一版截图中大型卡片背景已取消，三个默认旧 AVIF 的像素放大明显减轻；但水泵像素主体底部、温室主体底部和熔炉底部分别停留在不同高度，视觉上像悬浮卡贴。
- 问题来源是三类旧素材的**透明画布上下留白各不相同**，单纯同一张 Image 的 `object-position:bottom` 无法让绘画主体底部对齐。
- 只针对 `data-art-tier=legacy` 提供水泵 34%、温室 22%、熔炉 2% 的**画布内部相对偏移**，并与保守缩放联合使用。百分比基于图片盒子大小响应式变化；不改变 station button 的交互热区、铭牌位置或 15 格真实 Pixi 地块。
- 显式 `machine-art=review` 的 512px 高清原画审核不接受该旧素材偏移，以免为不同透明留白的候选带来错误投影。Playwright 同时断言 legacy 缩放上限和实际纵向变换，验证不是单纯 CSS 文档注释。

## R10.1 · 生产状态驱动的桌面反馈（同日）
- 同类多设备的全景代表优先级改为 **玩家明确选中 > 实际 working > 实际 blocked > idle**，同一状态内再比较等级。避免高级设备停工时遮住低等级但正在工作的设备；完全采用 `presentWorkshopStations()` 和 `inspectMachineSignals()` 的真实只读投影，不建立第二套生产判定。
- 设备下方新增真实机器暂存量与状态可读文字；工作中的地面光斑缓慢呼吸，缺料设备则收敛光亮并降低饱和度。仅 CSS、现有 DOM 和 React 只读数据，不新建 WebGL/Pixi 资源、不合成虚假的产出粒子。明确遵守系统减少动态效果。
- 新增 Vitest 对活跃设备优先展示、显式选中、数据不可变的回归，并在桌面 1440×900 浏览器验收真实生产状态、暂存数字和减少动态模式，生成 `desktop-workshop-production-feedback-1440.png`。
- 后续仍需真正的高清透明工坊原画、工匠作业动作与设计稿逐项对比；本阶段只改善 **可信状态与层次**，不等于美术原画已经通过审核。

## R10.2 · 工匠与设备协同层次 + 512px 原画对照
- 将普通 PC 全景中工匠的极小浮动头像改为位于真实设备旁的 **独立角色肖像铭牌**；使用仓库现有的泉泡、青枝、炽角各自 `face.webp`，明确不是伪造的全身工作精灵。只在设备实际派有工匠时出现，缺料状态收敛饱和度，运转状态有幅度很小的呼吸动作。
- 始终使用唯一的 `projectMachineProduction(world)` 决定预计当班产量和相邻材料实际供给是否接通；没连通的生产箭头不再全部常亮。熔炉的产出直接进入共享仓库，所以原先误导性的“设备暂存 0”改为“晶核直入仓库”。
- PC 全景不仅尊重系统 `prefers-reduced-motion`，还遵重游戏内 `monster-apartment:gothic-motion-reduced` 用户设置；通过事件订阅同步停止工匠与地面动效，不额外建立 Pixi ticker 或引入 WebGL 资源。
- `?machine-art=review` 现可在 512px 九张透明候选与旧素材之间原地对照，并带有“仅供原画审查”标识；普通玩家没有这组控件。所有候选 `status:review` 不变，Lv.2 工作图集仍 pending，不把尚未经人工美术审核的图像提升为正式资源。
- 浏览器定向回归覆盖 1440×900 的角色解码、真实预期产量、材料路线、减少动效、候选对照、没有意外存档写入，并输出独立截图。未声称创作全新正式原画。

## R10.3 · 真实机体光效研究与工匠全身 CG 发布门禁（2026-11-09）
本阶段严格区分三类东西：**九张 512px 静态设备候选图**、**针对其中 Lv.2 候选的四帧光效研究图集**与**真正的手绘机械工作帧**。第三类目前仍未交付；第二类不冒充机械移动，不写入正式游戏。

### 可重复生成与只读审核
- `v2/scripts/prepare-painted-machine-light-study.mjs` 读取已经清洁底部白边的 Lv.2 512×512 审核图片，按设备真实色材（水蓝、植绿、炉火）对**机体已有像素**进行少量亮度与扫光调整。四帧的 Alpha 轮廓完全一致，没有悬浮新零件，也不会将旧程序绘制的活塞叠上新机体。
- `v2/scripts/build.mjs` 在独立的 `dist/assets/review/machines/{craft}/light-study.webp` 生成三个 2048×512 的 WebP 图集，索引名为 `reviewLightStudies`。这是**构建产生的 QA 研究件**，不新增仓库正式美术文件；不填 `working`、`reviewWorking`，也不修改 `machine.*.working` 的 `pending` 状态。
- `/workshop/?machine-art=review` 的设备原画审核面板可逐帧检查四种光效状态或按 320ms 自动回放，且清晰标注“同机体光效研究 / 非机械动作 / 未批准”；系统与游戏内减少动态效果仍会阻止自动播放。普通 `/workshop/` 没有入口、不请求这些资源。
- 原画正式审核仍需检查：三类设备各三级独立结构、暗金和红紫材质、透明边缘、地面锚点、比例与 1440×900 设计稿构图。光效通过不能取代完整机械运动、审批或未来角色全身 CG。

### 工匠全身 CG 资源合同
- 已在 `v2/art/asset-pack.v1.json` 注册泉泡 brook / 青枝 fern / 炽角 cinder 三张独立 `worker.*.full`：每张 512×768 **真实透明** WebP，底部锚点 (0.5, 0.98)，初始 `status:pending`。它们**尚未创作或入库**，不能使用 512px 头像拉伸假装全身工匠，也不能将三个角色复用一张脸。
- 后续收到三张独立原图时，运行 `cd v2 && npm run art:import-workers -- /path/to/candidates`。脚本批次检查图片尺寸/大小、透明度、边缘裁切、三张是否重复和 SHA-256，**仅置为 `review`**。
- QA 的工作项包括成年人体比例、三人脸型差异、服装与手持工具、完整鞋底、透明残边、月夜材质与机器比例；经过人为比对并记录审核证据后才允许显式填写 `approval.visualReviewed=true`、`approval.evidence` 和 `status:ready`。
- `v2/scripts/audit-art.mjs` 会阻止缺 SHA/Alpha/人工批准的 `ready` 工匠或设备 CG。构建读取相同清单而非检测文件是否存在；未审核的全身图片只能生成 `review/workers`，正式版仅部署 `workers` 的已批准图片。Pixi 已接入静态 512×768 全身图加载，画作缺失时保持经过验证的八帧人形过渡精灵，不产生资源 404。
- 构建会清掉之前 `dist/assets` 里可能残留的机器、工匠正式/审核输出，避免审批撤回后旧文件继续公开。没有引入 Pixi 新纹理的逐帧分配、新 ticker 或存档升级。

### 交付与验收
- `npm --prefix v2 run audit:art`、`npm --prefix v2 run typecheck`、`npm --prefix v2 run build`，以及原有 Next/TS/Lint/Vitest 检查。
- Desktop Visual Review 在 1440×900 验证图集实际为 2048×512、四帧颜色发生变化但透明轮廓一致、每帧可选、减少动态设置有效、存档无写入、普通玩家依然没有审核图集/工匠正式资源；保存独立浏览器截图。
- 结论仍为 **R10.3 光效技术预览与资源发布门禁完成，不代表正式设备 CG、全身工匠 CG 或机械动画完成。**

## R10.4 · 真实班次结算的 PC 全景动效（2026-11-09）
- **真实事件、真实数值**：在 `WorkshopCinematicStage` 观察已连接存档的 `world.day` 增量，只有实际 `runShift()` 结算并写入 `world.last` 后，才在三台代表设备旁短暂显示上一班的水汽、孢子、晶核产出。这些数字取自唯一的 `DailyProduction` 报告，显示的是**同类全部设备合计**，不是推算某一台机器的独占收益；没有新增游戏经济、定时器或伪造资源。
- **Motion for React，非 WebGL**：利用已锁定的 `motion/react` 库做约 3 秒的浮动淡出。工坊现有 Pixi 15 格、机械部件和生产流水线不变；PC 全景仍没有新 WebGL 对象。屏幕阅读器用 `aria-live` 接收真实报表。
- **减少动态效果**：系统或游戏内禁用动态时显示静态可读的最近一次新结算，不播放上浮效果。淡出完成由 Motion 回调收口，无常驻 CSS 无限循环、动画帧轮询或额外保存动作。
- **重载防重放**：`workshop-client` 只有在真实世界存档与 Pixi runtime 都就绪时才通知 PC 全景开始观察日期；此前用于加载占位的 `newWorkshop()` 不能被误认成第一次生产。回到页面、刷新页面、旧存档日数较大、用户重置世界，都不应弹出虚假生产奖励。
- **实际可用的美术决策**：本轮尝试的外部风格探索仅是概念素材，未匹配已批准的哥特酒红与独立成年工匠肖像，不进入正式美术清单；三张 512×768 独立全身角色 CG、设备同机体机械动作继续需要真实绘画和人工视觉审核。不会将画风不一致的概念图强行替换为正式立绘。
- Playwright 在 1440×900 下种入真实三工位流水线，确认三种产出都按真实 `DailyProduction` 为 +2、无障碍播报、系统减少动态静态呈现、存档天数由 1→2、刷新后不重演、正常动态一次性淡出，以及再结算实际来到第 3 日；保存截图 `desktop-workshop-real-settlement-r104-1440.png`。移动端继续采用原 Pixi 棋盘，不新增全景 DOM。
