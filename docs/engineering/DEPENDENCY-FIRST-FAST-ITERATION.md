# 怪物公寓 · 成熟依赖优先、快速迭代工程规范

> 生效范围：本仓库后续所有设计、开发、修复和发布阶段。与 `AGENTS.md` 同步执行。

## 1. 先查成熟方案，再决定自研

新功能先检查现有库是否能直接解决：Next.js/React 负责路由及组件，Tailwind v4 管视觉样式，Motion 管动画，PixiJS 管 2D 特效，Zustand 管客户端状态，Dexie 管 IndexedDB，Lucide 管图标。避免新造图片优化服务、图标系统、路由框架、缓存框架、动画引擎等。

引入新依赖前，确认 ①需求确实存在且现有依赖不足；②库持续维护、版本稳定且有活跃社区；③许可证、安全和包体积合理；④兼容 TypeScript、Next.js 16/React 19、静态导出与 GitHub Pages 的 `/monster-apartment/` basePath；⑤不会破坏本地存档和移动端性能。满足则直接复用，并写明依赖用途、锁定版本和迁移范围。禁止盲目批量安装热门库。

## 2. 轻量质量闸门（每次普通 push / PR）

工作流 `Quality`：`checks`（稳定依赖审核、美术检查、typecheck、lint、Vitest）；`pixi-v2-scaffold`（Pixi 类型、贴图资产、构建）；`static-export`（Next 静态构建、图片导出路径审计、七个正式路由的静态文件）。全部通过后，原有 Pages 工作流可部署。删除重复构建，避免单次提交运行全量浏览器套件并互相取消。

## 3. 浏览器验证改成按需触发

GitHub Actions → **Gameplay Browser Review** → Run workflow：
- `smoke`：七个页面能否启动、主要导航是否正确等少量浏览器验证；改动涉及首次加载、路由、WebGL 挂载时建议执行。
- `full`：完整 Playwright E2E + 已配置的游戏截图产物。大型玩法更改、版本冻结、正式里程碑、重要上线验收执行。

默认不因尚未运行全量 E2E 而阻止前期快速迭代；但涉及经济、存档、付费性质数据的错误不得因此省略针对性测试。大型正式版本**先跑 full，核对通过后再宣布里程碑验收**。CI 轻量通过与人工完整 E2E 是不同级别，不应混淆。

## 4. 验收看真实效果，不看提交次数

每次 UI 改动明确用户可直达的页面、实际可见差异、版本标记。重大视觉改动在手动 `full` 中生成桌面和移动截图，并与归档设计图比较。Github 提交≠质量通过≠Pages 部署成功；线上验收必须查看对应提交 SHA 的部署结果。

## 5. 保护现有工程

七正式路由、保留现有玩家存档、原画和精细哥特黑金布局为硬约束。添加第三方库也不得更改抽卡概率、生产收益或资源扣除逻辑。功能逻辑优先用纯函数和少量 Vitest 验证，浏览器只测浏览器特有问题。
