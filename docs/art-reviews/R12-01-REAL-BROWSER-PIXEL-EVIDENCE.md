## 1. 本轮实测覆盖

Chromium，进入欢迎页后的现有玩家状态，`prefers-reduced-motion`。七个正式路径 × 四组视口 = **28 份路由样本**，其中大厅、公寓、工坊、委托、仓库各四份原始截图，合计 **20 张**。其余角色图鉴、月光街采集 JSON，但不应据此宣称两者已完成逐帧人工截图审核。

| 档位 | CSS 视口 | 设备 DPR | 用途 |
| --- | --- | --- | --- |
| 桌面基准 | 1440×900 | 1 | 现有素材普通屏 |
| 高密桌面 | 1648×928 | 2 | 大屏高密采样压力 |
| 普通手机 | 390×844 | 2 | 竖屏背景安全裁切 |
| 矮屏手机 | 390×550 | 2 | 极端高宽比、面板遮挡 |

取证字段：HTML 图片 `currentSrc` / `naturalWidth` / `naturalHeight` / `objectFit` / 真实矩形，背景图片实际加载尺寸及 CSS `background-size`，Canvas backing store 与 CSS 尺寸。所有显示倍率依`devicePixelRatio × max(renderWidth/srcWidth,renderHeight/srcHeight)`估算 **cover 模式的有效采样比**。高于 1 不自动等于「该帧明显模糊」，其余 `contain` 或非 cover 背景不套这个公式。

## 2. 测得的关键风险

| 位置 | 现场图像来源与实际尺寸 | 实测有效采样比 | 事实与修复方向 |
| --- | --- | --- | --- |
| 大厅满屏背景 | `lobby-hero-v3.webp` · 1587×991 | 桌面 1648×928 DPR2：**2.08×**；手机 390×844 DPR2：**1.70×** | 高密屏必须放大源图细节；需要原生更大版本和独立手机构图，不能简单把已有 V3 插值放大称 HD |
| 公寓公共空间 | 与大厅相同 `lobby-hero-v3.webp` | 桌面 1648×928 DPR2：**2.08×**；手机 390×844 DPR2：**1.70×** | 不只是清晰度，实机截图确认**公寓没有自己的建筑公共空间身份**；#16 的独立绘景优先级 P0 |
| 委托与仓库上部小图 | 两页都是 `moon-workshop.avif` · **360×228** | 桌面 1440×900 DPR1：**1.59×**；1648×928 DPR2：**3.68×**；390×844 DPR2：**1.91×** | 真实小图被放大为大型横幅，最明确的换图候选；同时两个地点依旧共用大厅全屏背景，不应仅用换色假装独立 |
| 角色图鉴三位过渡头像大卡 | `face.webp` 各 **512×512** | 1648×928 DPR2，部分画布按 **365×763 CSS** 显示，cover 有效比约 **2.98×** | 平方头像承担竖长人物卡，模糊和大量裁切风险；必须走独立长画幅 CG，不应把脸图拉成长卡 |
| 月光街 / 工坊过渡绘景 | `town-moonlit-gate.webp` / `workshop-gothic-hall.webp` 均 1920×1080 | 月光街桌面 1648×928 DPR2 **1.72×** | 虽已有独立过渡图，仍未满足街区/锻造工坊的正式场景身份与高密屏需求 |

**工坊 Canvas 反证**：1648×928 DPR2 的 `canvas.width × height=2100×1290`，CSS 矩形约 973×598，每 CSS 像素实际约 **2.16×2.16**；390×844 DPR2 的 Canvas 1660×1640，CSS 约 464×459，约 **3.58×3.57**。因此不能把工坊视觉糊点粗暴归因于 Canvas backing store 分辨率太低；还须分别看 Pixi 相机缩放、底图贴图源尺寸、纹理过滤与具体层级。上述比例也**不是 GPU 显存占用**。

## 3. 从真实截图看到的场景重复

- 公寓浏览器截图仍是月纱坐在沙龙里的完整场景，左边叠六扇房门管理面板；不是纵深走廊与清楚的私室门口。
- 委托和仓库都在完全相同的月纱大厅绘景上叠右侧业务表；二者顶部又使用同一张 360×228 的工坊 AVIF 小图。场景只是标题和业务面板不同，缺少独立透视、道具和光线。
- 实测表只说明原因候选与身份重复。原图柔焦、编码损失、热点是否被遮挡等，还需审查截图局部与原画，不能据像素比率直接盖章。
