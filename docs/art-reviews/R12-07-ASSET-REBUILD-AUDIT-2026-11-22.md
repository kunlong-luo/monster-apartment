## 5. 工坊动态资源和小型素材：分清“尺寸”与“准入”

- `v2/art/asset-pack.v1.json` 中 **9 张 512×512 设备等级 WebP 明确为 `review`**，它们有独立外形及升级差异，目视检查的水汽泵 Lv1/Lv3 和炉 Lv3 都具有可识别轮廓。**先保留等待**透明边缘、锚点、等级差异、受光一致性、人审来源检查；只有不合格的重绘。文件位于 `production/machines` 路径**并不能**凌驾于 JSON 的 `status: review`。
- 3 张 2048×512 四帧 `working.webp` 图集为 **pending / 文件缺失**；没有对应 Lv2 机身视觉一致的画帧，不能用一张机器定帧复制四次装成动画。`workshop-painted-art.ts` 会回退 AVIF/程序化画。
- 3 位工匠的 `512×768` 透明作业全身纹理为 **pending / 缺文件**；Pixi 当前可回退到 `raster-sprites.ts` + `worker-canvas.ts` 中三人各 8 个 Canvas2D 过渡姿态。**这是代码生成的过渡纹理，不是已签审的独立人物精灵表**。
- 工坊月纱 NPC 的 `full` / `bust` / `idle` / `talk` / `trade` 5 个产物也由 `asset-pack.v1.json` 标为 pending；优先级低于玩家高频可见的三个作业工匠。
- `v2/art/moon-workshop.avif` 真实像素 **360×228** 是失败兜底，不可升格全屏背景；`garden/kiln/well-art-review.avif` 各 **320×320**，属于小辅助画；`moonstone-floor.avif` **146×146** 是重复平铺纹理，**不能只因尺寸小就判废**。
- `feature-postcards` 两张 **960×320** 只用于小幅海报；3 张身份肖像 **512×512** 只用于头像与缩略位。应核真实 CSS 框、DPR 与中心裁切后决定是否做升级版，而不是全部无差别重绘。

## 6. 封面、风格一致性和仓库资源卫生

- `world-cover.webp` 为 **1920×1080**，`world-cover-mobile.webp` 为 **900×1539**。本次预览可见封面中心的黑发成年女性与兽类，和当前已锁定的 V3 银发月纱**并非同一明确形象**；如果封面叙事主角本来不是月纱，应明确标注角色设定，而非直接认定错脸。**封面是否重绘先由剧情/品牌确认主角身份**。手机版还需检验 390×844 DPR2 的纵向有效采样和页面文字安全区。
- 2 张 `world-scenes` 过渡图来自 `winechan-gothic-manor` 审核路径；`source-manifest.json` 写有来源与发布者声称的授权，但这不是最终商业使用许可的人审。新的正式场景必须补齐版权/来源证据，且在游戏中有明确的地点功能与建筑语言。
- Git Tree 识别 **3 对完全相同 Git blob SHA**：`.aistudio/artifacts/brain/.../.tempmediaStorage/*.png` 与 `public/assets/aistudio/*.png`，每份图尺寸分别 3,279,821／3,154,947／2,726,560 字节；每一组出现两份，总计约 **9.16 MB 重复存储**。这些是参考图而非已经确认的生产画。先检查是否有页面实际引用 `public/assets/aistudio`，保留一份适当位置的来源记录后再决定清理，**本轮不删文件**。
- `public/art/a05/{foreground-ornaments,moonlight-tracery,rose-petal}.svg` 属于小 UI/装饰层；其价值与占比合理时**保留**。不要因为“禁止粗糙 SVG 人物”就误删所有 SVG。

## 8. 每张新图的统一验收协议

1. **先定用途**（角色身份头像、竖幅卡、透明演员、独立背景、原画中热点、机器图集、小海报），不用一种图跨多种尺寸承担所有职责；同一角色跨页面保持身份。
2. **原生证据**：原始来源/许可、版本/源 PNG 或分层文件、SHA-256、真实自然宽高、WebP/AVIF 输出、是否有透明通道；不允许旧图插值放大后标“原生”。
3. **定性人审**：角色脸型、姿态、武器握持、衣装、完整脚/耳/角、画面焦点、背景真实地点、道具、材质层次、AI 伪文字、水印与画面烘焙 UI；审核员/日期/理由须真实。
4. **真实浏览器截图**：至少 1440×900 DPR1、1648×928 DPR2、390×844 DPR2、390×550 DPR2，记录 `currentSrc`、`naturalWidth×naturalHeight`、画面几何、`object-fit/cover` 裁切、是否命中回退及 LCP/加载；对照旧版本标注模糊点。**不是单纯满足 WebP 尺寸就通过。**
5. **角色特定**：五卡 G0–G7 + `pnpm audit:character-cg`；私人房间 `pnpm audit:room-art`；S02/S05/S06 `pnpm check:design`（含 R12 场景准入）；设备按 `v2/art/asset-pack.v1.json` 实际 status/锚点与相应审核脚本。
6. **分阶段合并**：先 review，再具名 signed approved，最后清单与运行时 production；只替换一批可观察图，保留安全回退。记录 Quality / Visual / Browser / Pages 在同一 SHA 的结论，**未通过不宣称正式高清已上线**。
7. **不破坏玩法**：七个主路由、六间公寓房索引、已有私人房剧情和热点、工坊 15 格、卡池概率与保底、原有存档键和设备状态均不因更换图而变化。

**审计边界和下一次检查**：本轮仅写文档和资产台账，未制作任何新图、未自动签批任何权利或身份、未修改生产 manifest。最值得首先提交的试点是**S05 PC/手机独立委托场景**或**青枝拉弓 CG**各一套真实制作与审核证据，以证明“规范→原生原画→真实浏览器→入库”闭环，然后扩批。
