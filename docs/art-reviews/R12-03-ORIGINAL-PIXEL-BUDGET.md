# R12.0.5 · 六张原始绘景的像素预算和可复现核验

> 2026-11-17 · [#24 图片模糊](https://github.com/kunlong-luo/monster-apartment/issues/24) / [#16 独立绘景](https://github.com/kunlong-luo/monster-apartment/issues/16)
>
> **所有 S02/S05/S06 原画仍为 review。** 本文是通过真实原始 PNG SHA-256 和 IHDR 字节完成的像素诊断；不是绘画品质、授权或发布验收通过的证明。

## 1. 不再用输出文件名判断是否高清

本次直接核对对话中 `r12-six-original-scenes-review-2026-11-16.zip` 的 `review-manifest.json` 与六张**完整 PNG 原图**，逐份检查：

- 原图字节 SHA-256 与审稿清单 / 项目 `r12-scene-manifest.json` 一致，而非对比一个缩略图文件名。
- PNG `IHDR` 原生长宽（非把图片插值导出后填写的宣称尺寸），且全部六张 SHA 不重复。
- `background-size: cover` 在四档位需要的**实际设备像素采样比** `max(CSS宽×DPR/图宽, CSS高×DPR/图高)`。
- 同时保留最低制作门槛 PC 2560×1440 / 手机 1080×1920。对高密屏的放大风险另行报告，绝不把“达到最低尺寸”说成在所有设备上 1:1 像素清晰。
- 对于用户实际反馈的图片模糊，`effectiveCoverScale > 1` 代表采样不足**风险**，不代表一定肉眼模糊；小于等于 1 也不证明已经通过画质审查。

| 场景 | 画幅 | 原图实际尺寸 | 生产最低值 | 高密屏实际有效放大 | 结果 |
| --- | --- | ---: | ---: | ---: | --- |
| S02 公寓 | 桌面 | 1672×941 | 2560×1440 | 1.972× | 不合格 |
| S02 公寓 | 手机 | 941×1672 | 1080×1920 | 1.010× | 不合格 |
| S05 委托 | 桌面 | 1672×941 | 2560×1440 | 1.972× | 不合格 |
| S05 委托 | 手机 | 941×1672 | 1080×1920 | 1.010× | 不合格 |
| S06 仓库 | 桌面 | 1672×941 | 2560×1440 | 1.972× | 不合格 |
| S06 仓库 | 手机 | 941×1672 | 1080×1920 | 1.010× | 不合格 |

**采样设备**：桌面放大值使用 1648×928 CSS、DPR2；手机使用 390×844 CSS、DPR2。其他两档 1440×900 DPR1 和 390×550 DPR2 也会被脚本逐张保存。六张照片均核对通过原始 SHA 和实际 PNG 长宽，**0/6 达到最低原生规格，0/6 通过全部档位不放大**。

## 2. 新代码：直接拿原图 ZIP 检查

下载本轮聊天的六原图 ZIP 并解压：

```bash
unzip r12-six-original-scenes-review-2026-11-16.zip -d /tmp/r12-art
pnpm art:r12:inspect --source-dir /tmp/r12-art --out /tmp/r12-evidence
# 输出 JSON + Markdown，审稿模式仅报告不晋级，不修改源码/生产图片

pnpm art:r12:inspect --source-dir /tmp/r12-art --out /tmp/r12-evidence --strict true
# 对本轮的 6 张低于阈值的图片应退出非零状态，用作正式替换 PR 的质量门禁
```

脚本：`scripts/verify-r12-source-pack.mjs`。自动测试：`scripts/tests/r12-source-pack-pixel.test.mjs`（已接入 `pnpm check:design`）。源码和权限审计仍由已有 `scripts/audit-r12-scene-art.mjs` 负责；本脚本只补齐源包像素与四档实际采样检查。

## 3. 下一次需要实际制作的东西

1. **先重新绘制足够高频细节的原生桌面图**，至少 2560×1440；但以 1648×928 DPR2 为不放大目标时应考虑至少 3296×1856（接近 16:9），不能只靠插值。这是采样预算，不是强制要求固定为 4K。
2. 手机独立竖版至少 1080×1920；两种 390 宽手机高度都需要检查可交互热点和人物安全区。

4. 正式原图与两个 WebP 输出放入 Git 仓库，通过 `check:design` 真实 PNG/SHAs、人工授权和审稿、路由替换、四档原始截图及同一 SHA 的 CI，之后才考虑晋级 `production`。
5. 在新资源**实际接入和线上对照前**，#16/#24 保持开放，不能将 6 张候选和工具建设冒充模糊已解决。

## 2026-11-17 · 可立即移除的低清原型横幅

R12 实机截图显示：S05 委托、S06 仓库顶部横幅将同一张 `v2/art/moon-workshop.avif` 原型图铺满大面积区域。该文件本身为约 360×228，绘制场景还是工坊，并不属于这两个地点；它对桌面横幅的放大是可确定的模糊来源。

当前修正分支只对**尚未晋级的旧横幅**做以下处理：

- 删除未审核时铺满整张横幅的 360×228 工坊图，改用清晰的临时暗色分层底板，保留委托/库存标题、真实按钮和布局。
- 一旦 `R12SceneManifest.status=production`，仍正常使用经审核的 PC/手机独立图片；`?r12-art-review=1` 所选本地原图仍可在实机横幅与场景中预览。
- Playwright 同时确认 **review-only** 路由下不再加载那张工坊横幅原型，以及生产晋级后仍要解码正确的双端图片。

这只是**局部去除已证实的模糊图块**，不是重新绘制独立场景，也不意味着 S02/S05/S06 的主背景已经变成高清。#16/#24 均需保持开放直到真正的独立原生高清绘景通过人工验收并上线。


## R12.0.8 · 人物图鉴的 512×512 头像不再冒充高清大立绘

除 S02/S05/S06 的正式绘景外，#24 还包括 A05 人物图鉴的源图采样：部分居民只有 **512×512** 的肖像，而非完整人物 CG。此前鉴赏画框随浏览器高度扩张，在 DPR2 档位会把低分辨率肖像明显放大。

本轮代码在 `CharacterGalleryArtwork` 中通过静态图源自带的真实 `width/height` 限制**未有正式 CG** 的肖像画框：按 DPR2，每张最多使用源图宽高的一半 CSS 像素，同时保留鉴赏窗口与人物筛选；使用独立 CG 候选的画作不受此限制。新增 Playwright 在 1648×928 检查 512×512 头像不超过 256×256 CSS 像素，且手机无页面横向溢出、神话人物大画幅不被错误缩小。

这是**消除已知采样放大**，不是把肖像改造成高清全身 CG。正式人物 CG 仍须按独立美术制作计划另行审核；三个场景主背景也仍需原生高分辨率素材。


## R12.0.9 · 横幅加载失败不允许回退到错误场景缩略图

在 R12.0.7 移除 S05/S06 **未审核** 状态的 360×228 工坊横幅后，进一步排查发现旧调用仍为未来 `production` 横幅传入 `fallbackSrc=moonWorkshopPainting`。这意味着一旦已批准的独立绘景遇到网络或解码错误，两次失败后仍会重新显示不属于委托/仓库的低清工坊图；仅检查正常加载状态不能发现这类回归。

修复范围严格限于 S05/S06 横幅：
- 清除这两页对错误工坊缩略图的导入和传参；正式原图与可选本地审稿图均遵循同样原则。
- 继续由已有 `ReliableImage` 发起单次重试；只有连续两次图像加载错误，才使用已存在的 `mw-world-hero-pending` 清晰本地底板。视觉上不会以 360×228 旧场景冒充已审核原画。
- 新增针对本地审稿图的真实页面事件回归：图像解码后模拟连续两次失败，应出现底板而不能出现工坊缩略图。正常加载和未来正式双端图的既有检查继续保留。

**性质与限制：** 这是故障路径的防模糊回归，不是新的独立美术资产、授权审批或高清原图发布。主背景仍可能重复，S02/S05/S06 的六张 review 原图仍未达到原生高清像素门槛；#16/#24 仍开放。


## R12.0.11 · 正式美术准入同时检查高密屏 cover 采样

审计发现原有两条路径标准不一致：`art:r12:inspect --strict true` 会把 1648×928 / DPR2 的像素放大视为失败，但 `scripts/audit-r12-scene-art.mjs` 对已签字的 `production` 作品只检查最低 2560×1440 桌面源和 1080×1920 手机源。这可能让一张名义满足“2K”原生尺寸的横图通过生产门禁，实际在主目标 PC 高密屏全屏显示时仍需放大。

这次将四个**实际截图设备**的 `background-size: cover` / `object-fit: cover` 采样规则抽取到 `scripts/r12-pixel-geometry.mjs`，使预审工具与正式生产准入共享算法和目标档位：

- PC 1440×900 / DPR1、PC 1648×928 / DPR2；
- 手机 390×844 / DPR2、390×550 / DPR2；
- 每张**真实原始 PNG** 与对应的**最终正式 WebP 输出**必须在相关档位没有大于 1.001 的有效像素放大；检查发生在真实字节和原图 PNG IHDR / WebP 帧尺寸核验后，**单纯提高 manifest 声明尺寸或插值原图不可通过可信来源、人工审批与非插值声明的联合门禁**。
- 现有最低生产规格 2560×1440 / 1080×1920 **没有取消**，但桌面 16:9 要对 1648×928 / DPR2 不放大，画面实际至少应接近 **3296×1856**，并同时保障 1440×900 的裁切；这仍只是像素风险筛查，不是对清晰度与授权的人工签字。

负向测试专门覆盖两种此前可能混淆的情况：1）2560px 的真实源 PNG 已达最低但在 DPR2 被拉伸；2）原始 PNG 已足够细，导出 2560px WebP 后又在游戏里被放大。两种情况都必须阻止正式晋级。

**未完成边界**：当前 S02/S05/S06 仍为 `review`，0 套新正式双端高清作品进入线上；本次不是美术换图或用户可见的画质完成。真正的下一项工作仍是原生高细节独立绘景源图入仓、版权和视觉审稿、四档实机截图、同一 SHA CI 与 Pages 验证。
